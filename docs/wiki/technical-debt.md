Первоначальная нестабильность TokenStore воспроизведена исполнением исходного класса из git
в отдельной временной БД: 24 потока, параллельные lookup/record дали None и InterfaceError.
Защита охватывает execute, fetch и транзакцию; не подставляет значения вместо повреждённого чтения.

## Практические ограничения

- Компактация по умолчанию строит сводку через модель; исходная история сохраняется.
  При автоматическом резервном сжатии возможны явно помеченные неполные выдержки.
  Точного токенизатора нет: используется приблизительная оценка ceil(байты JSON / 3) + 64.
  max_turn_tokens=0 отключает суммарный бюджет; положительное значение задаёт явный лимит.
- Защита правами auth.json не шифрует секреты. Shell/MCP не изолированы ОС-песочницей.
- Старые сессии без отпечатка подключения остаются совместимыми; для строгой проверки создайте новые.
- Браузерные проверки используют подставленный DOM, визуальная проверка отдельно.
- Квоты и блокировка запусков рассчитаны на один процесс сервера; распределённые квоты,
  DNS pinning и нативные протоколы не-OpenAI API остаются отдельными будущими задачами.

## Состояние перед 1.0

Проверки установленных CLI, чата/API и OpenTUI в PTY добавлены в CI. Устаревшее
утверждение об отсутствии LLM-суммаризации исправлено. Текущая сборка проверяется
с закреплёнными зависимостями; тестовый клиент Starlette предупреждает о будущей
замене обвязки httpx. Это остаётся техническим долгом тестов, не меняет runtime-протокол.
Реальные подключения и эксплуатационные блокеры перечислены в [заметках 1.0](release-1.0.md).
