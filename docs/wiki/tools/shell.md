# Инструмент: shell

Инструмент `shell` выполняет команду оболочки в рабочей папке сессии.

Код: [`agent/tools/shell.py`](../../../agent/tools/shell.py). Тесты: [`tests/test_tools_shell.py`](../../../tests/test_tools_shell.py).

| Аргумент | Описание |
|---|---|
| `command` | строка для `<shell.executable> -c` (по умолчанию `/bin/bash`) |
| `timeout` | секунд; по умолчанию `shell.timeout` (120), не больше `shell.max_timeout` (600) |

Результат: `exit code: N` и вывод (stdout и stderr вместе, в порядке появления). Код ≠ 0 —
результат с ошибкой (`ok: false`), модель это видит. Права по умолчанию — **ask**.

## Как запускается

- cwd — рабочая папка сессии, stdin — `/dev/null` (интерактивные команды не дождутся ввода);
- **окружение урезано**: только переменные из `shell.env_passthrough` (`PATH`, `HOME`, `LANG`, …)
  + `shell.env` + `GWAGENT_SESSION`. Токены и ключи процесса (`GW_TOKEN`, `UPSTREAM_API_KEY`, …)
  в команду не попадают;
- своя группа процессов (`start_new_session`): по таймауту или отмене убивается вся группа
  (`SIGKILL`), включая фоновых потомков (`sleep 30 &`);
- вывод копится не больше `8 × max_tool_output_chars` байт, затем обрезается до
  `max_tool_output_chars` (начало + конец). По таймауту возвращается то, что успело выйти.

## Это не песочница

Команда выполняется с правами пользователя, под которым работает агент: видит его файлы, сеть,
может выйти из рабочей папки (`cd /`). Защита только в правах и хуках:

- в CLI каждый вызов подтверждается, если нет `allow`-правила;
- на сервере — отдельный системный пользователь для шлюза, в профилях — `deny: ["shell"]` или
  узкие `allow`, хук `PreToolUse` с политикой (пример — [hooks.md](../hooks.md));
- нужна изоляция — `shell.executable` можно указать на обёртку (`bwrap`, `firejail`, `docker exec`),
  которая принимает `-c <команда>`.

Подробнее — [security.md](../security.md).
