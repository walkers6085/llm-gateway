# Бенчмарки модели

Отдельный пакет `bench/`: реальные запросы к OpenAI-совместимому API, без фреймворков,
токенизаторов и внешних корпусов. Обычный pytest проверяет реализацию офлайн и не оценивает модель.

```bash
GW_TOKEN=gw-… venv/bin/python -m bench --model MODEL --quick
venv/bin/python -m bench --list
venv/bin/python -m bench --model MODEL --suites needle,reasoning --set needle.lengths='[2048,8192]'
venv/bin/python -m bench --compare data/bench/first.json data/bench/second.json
```

`--url` по умолчанию `http://127.0.0.1:7700/v1`; авторизация из `GW_TOKEN`.
`--output` — каталог JSON и Markdown (по умолчанию `data/bench`, исключён из git).
Запуски расходуют токены выбранного сервера. Реальные замеры нужно запускать отдельно,
когда шлюз настроен. Сервис CLI не включает.

## Наборы и методика

- `speed`: повторные потоковые ответы; медиана и p95 TTFT (секунды), медиана скорости
  генерации после первого чанка. TTFT включает сеть и очередь. Usage даёт число токенов;
  без него считаются чанки, что не равно токенам. Результат каждого запроса хранит
  `usage_reported`. Раннее завершение ответа может уменьшить фактическую длину генерации.
- `context`: проба нижней границы, верхней, затем двоичный поиск принимаемого входа.
  Только ошибки 400/413/422 с указанием контекста считаются ограничением окна.
  Ошибки сети, авторизации и лимитов останавливают измерение. `context_tokens` —
  максимальная успешная оценка длины входа; `ceiling_reached` означает, что достигнут
  потолок эксперимента, реальное окно может быть больше. При отсутствии успешных проб
  возвращается 0. Это не тест качества удержания информации и не точный лимит токенизатора.
- `needle`: уникальный код среди синтетических предложений, сетка длин и глубин вставки.
  Ответ должен точно совпасть с кодом после удаления внешних пробелов. Ошибки API
  считаются провалами. В отчёте сохраняются ожидаемые коды и ответы для проверки.
- `reasoning`: воспроизводимые задачи `(a+b)*c` и инструкция отвечать только числом;
  проверка точная. Это узкая проверка арифметики и формата, а не универсальная оценка интеллекта.

- `tools`: выбор weather или multiply, точные аргументы, валидная схема вызова,
  а также ответ без ненужного инструмента. Три случая на повтор; tool_choice не принуждается.
- `structured`: плоский и вложенный JSON с массивом и nullable-полем. Отдельно считаются
  соответствие схеме (`schema_valid`) и полное совпадение значений (`passed`). Проверка
  следует подмножеству JSON Schema из `agent/schema.py`; Markdown, NaN/Infinity,
  повторяющиеся ключи и лишние поля не принимаются. Принудительный response_format
  не используется: проверяется способность модели соблюдать инструкцию.
- `chain`: три хода — find_product, get_price, итоговая цена. ID товара и цена выдаются
  симулятором только после правильного вызова; модель должна использовать результаты
  предыдущего инструмента. Проверяются порядок, аргументы, уникальные id вызовов и
  точный итоговый ответ. Лишние вызовы, ранний ответ и неверные аргументы завершают случай
  провалом. Это ограниченная цепочка из двух инструментов, не полный тест автономного агента.

Средняя оценка качества 0–100 включает `needle`, `reasoning`, `tools`, `structured` и `chain`
с одинаковыми весами.
Скорость и размер окна в неё не входят. Сравнивайте одинаковые конфигурации; `--quick`
предназначен для проверки работоспособности. Наборы с ошибкой исключаются из среднего,
поэтому всегда проверяйте статус и полноту отчёта. CLI возвращает 1 при ошибке набора,
2 при неверных параметрах; низкая оценка сама по себе не меняет код выхода.

## Настройки

Слои: умолчания → `--quick` → JSON из `--config` → повторяемый `--set ключ=JSON`.
Неизвестные ключи и неверные типы запрещены. Общие ключи: `seed=42`, `timeout=300` секунд.

| Набор | Ключи и умолчания | Быстрый режим |
|---|---|---|
| speed | repeats=5, max_tokens=256 | 2, 64 |
| context | min_tokens=1024, max_tokens=32768, steps=8 | max_tokens=4096, steps=3 |
| needle | lengths=[1024,4096,16384], depths=[0,.25,.5,.75,1], repeats=2 | lengths=[1024], depths=[0,.5,1], repeats=1 |
| reasoning | cases=12 | cases=3 |
| tools, structured, chain | repeats=2, max_tokens=256 | repeats=1 |

Длины положительны, глубины 0–1, количество повторов и шагов не меньше 1.
Калибровка `Context.chars_per_token` отправляет два текста разной длины и использует
разность prompt_tokens. Без usage применяется оценка 3.2 символа/токен для русского
и 4 для английского; fallback сохраняется в `shared`. Тексты воспроизводимы по seed.
Накладные токены инструкции и ответа не включены в задаваемую длину стога.

## Код и проверки

`bench/client.py` собирает SSE, usage, tool_calls и тайминги; `runner.py` проверяет настройки,
изолирует ошибки наборов, сохраняет отчёты и сравнивает метрики; `textgen.py` генерирует
фон; `suites/__init__.py` содержит реестр и базовые методики, `suites/agent_tasks.py` —
агентские проверки и строгий разбор JSON; `__main__.py` — CLI.
JSON содержит настройки, общие калибровки, метрики и детали каждого случая.
Токен авторизации в отчёты не записывается. Не включайте секреты в URL API.

`tests/test_bench.py`: MockTransport проверяет путь `/v1/chat/completions`, SSE и usage;
поддельная модель проверяет успешное извлечение, арифметику, поиск границы окна,
сетевые ошибки, настройки и имена файлов отчёта. Запуск: `venv/bin/pytest -q tests/test_bench.py`.


## Провайдеры

Общий [менеджер провайдеров](../providers.md) используется и CLI агента.
Если существует `~/.config/gwagent/providers.json`, используется его `default`.
Явный `--provider NAME` выбирает подключение, `--providers-file FILE` — другой реестр,
`--model MODEL` переопределяет модель провайдера. Без реестра работает прежний URL шлюза.
Явный `--url` обходит реестр; вместе с `--provider`/`--providers-file` он запрещён.
Отчёт сохраняет имя провайдера, URL и фактическую модель, но не токен.

```bash
venv/bin/python -m bench --provider local --suites tools,structured,chain --quick
```

`tests/test_bench_tasks.py` проверяет положительные и отрицательные случаи: неверный инструмент,
аргументы и JSON, лишний вызов, выдуманный ID, повторный id, ранний ответ, неверную цену,
ошибки API. `tests/test_bench.py` также проверяет выбор подключения и модель в отчёте.
Внешние инструменты не исполняются: результаты цепочки генерирует безопасный симулятор.
