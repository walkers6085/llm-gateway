# CLI: gwagent

Код: [`agent/cli.py`](../../agent/cli.py), запуск — [`gwagent`](../../gwagent) (как `gwtoken`, сам
перезапускается из `venv/`). Тесты: [`tests/test_cli.py`](../../tests/test_cli.py) — против настоящего шлюза
в потоке и mTLS-апстрима.

Модель — через шлюз по токену `gw-…` (лимиты, allowlist и учёт токена действуют), инструменты,
MCP-серверы и хуки — **на машине, где запущен gwagent**, в текущей папке.

## Быстрый старт

```bash
export GW_TOKEN=gw-…                                   # токен от ./gwtoken create
mkdir -p ~/.gwagent
echo '{"gateway": {"url": "http://192.168.0.159:7700/v1"}}' > ~/.gwagent/settings.json
cd ~/projects/demo && /home/deb/llm-gateway/gwagent    # или ln -s …/gwagent ~/.local/bin/
```

Для CLI профиль агента у токена **не нужен**: агент работает локально и ходит только в `/v1`.

## Параметры

| Флаг | Описание |
|---|---|
| `-p, --prompt "текст"` | один запрос и выход; код выхода 0, если агент закончил (`done: stop`), иначе 1; 2 — ошибка настройки |
| `--cwd DIR` | рабочая папка (по умолчанию текущая); из неё же читается `.gwagent/settings.json` |
| `--model M` | модель (иначе `model` из настроек, иначе первая из `/v1/models`); сохраняется в сессии |
| `--provider NAME` | подключение из [менеджера провайдеров](providers.md) |
| `--providers-file FILE` | JSON подключений; используется его default, если нет --provider |
| `--settings FILE` | дополнительный слой настроек |
| `--resume ID` | продолжить сессию (достаточно однозначного начала id) |
| `-c, --continue` | продолжить последнюю сессию с этой рабочей папкой |
| `--allow-all` | `permissions.mode = allow_all` |
| `--read-only` | `permissions.mode = read_only` |
| `--tui` | интерфейс [OpenTUI](tui.md), требует Bun и `gwagent tui install` |
| `--plain` | обычный терминал; без флага TUI выбирается при установленных зависимостях и интерактивном терминале |
| `--json` | события построчно в JSON (для скриптов; формат — [agent-loop.md](agent-loop.md)) |

Токен: `gateway.token` в настройках или переменная из `gateway.token_env` (по умолчанию `GW_TOKEN`).

## Интерактивный режим

```
gwagent · my-model · /home/me/demo · сессия 3fa2c1d09e7b4410 · /help
› найди TODO в проекте и составь список
⚙ grep {"pattern": "TODO"}
  ✓ src/app.py:12:# TODO: кэш (4 мс)
Нашёл 3 места: …
```

| Команда | Что делает |
|---|---|
| `/new` | новая сессия (модель и папка те же) |
| `/sessions` | 20 последних сессий, `*` — текущая |
| `/resume <id>` | переключиться на сессию |
| `/model [имя]` | показать / сменить модель сессии |
| `/provider add NAME URL [MODEL]` | добавить подключение локально, без модели и сети |
| `/provider set NAME URL [MODEL]` | изменить URL/модель; для активного подключения создаётся новая сессия |
| `/provider [имя]` | показать подключения / переключить провайдер с созданием новой сессии |
| `/models` | запросить модели текущего подключения |
| `/tools [имя]` | инструменты с правами по умолчанию |
| `/mcp` | MCP-серверы: инструменты или ошибка запуска |
| `/help`, `/exit` | справка, выход (также Ctrl+D) |

**Ctrl+C** во время работы отменяет запрос (история остаётся корректной), в приглашении — просто
новая строка. Редактирование строки и история ввода — через `readline`.

## Подтверждения

```
? shell: rm -rf build
  (требует подтверждения; «всегда» добавит правило shell(rm -rf build))
  Разрешить? [y]es / [n]o / [a]lways:
```

`y` — разрешить, `n` или Enter — отказать, `a` — разрешить и запомнить правило в сессии.
Ctrl+C на вопросе — отказ и отмена запроса. В режиме `-p` без терминала (cron, пайплайн) спросить
некого — всё, что требует подтверждения, отклоняется; используйте `--allow-all` или `allow`-правила.

## Где что лежит

- настройки: `~/.gwagent/settings.json`, `<папка>/.gwagent/settings.json` ([settings.md](settings.md));
- сессии: `~/.gwagent/sessions.db` (`sessions.db`), владелец `local` ([sessions.md](sessions.md)).

## Примеры

```bash
gwagent -p "обнови README по коду" --allow-all
gwagent -p "сводка по логам" --read-only --json | jq -r 'select(.type=="text").text'
gwagent -c                                       # продолжить вчерашнюю сессию в этой папке
```


## Несколько провайдеров

[Менеджер провайдеров](providers.md) хранит URL, имя переменной ключа и модель по умолчанию.
Если существует его стандартный файл, `default` используется для новых сессий автоматически.
`--provider` выбирает провайдер явно, `--model` переопределяет модель подключения.
Без файла и флагов сохраняется подключение `gateway` из настроек.
В режиме провайдера пустой `token_env` разрешает локальный сервер без авторизации.
При прямом подключении запросы идут на URL провайдера; лимиты и учёт шлюза действуют,
когда выбран URL шлюза.

Смена через `/provider` создаёт новую сессию, чтобы история предыдущего подключения не
отправлялась новому. Для локальных сессий `profile=provider:NAME` сохраняет привязку;
при `--resume`, `--continue` и `/resume` восстанавливается её провайдер, даже если default
изменился. Явный конфликт `--provider` и возобновляемой сессии возвращает ошибку.
Используйте тот же `--providers-file` для возобновления сессий с нестандартным реестром.
Старые сессии с пустым profile продолжают использовать gateway из настроек.

## Доверие, диагностика и история

После установки из wheel доступны команды gwagent, gwbench и gwproviders без привязки к checkout.
Поддерживаемая платформа — Linux, Python 3.12+; используется fcntl, POSIX-группы процессов и bash.

```bash
gwagent trust                         # просмотр предупреждения и явное доверие текущему конфигу
gwagent trust --revoke                # отзыв доверия
gwagent config show                  # итоговые настройки и источники без секретов
gwagent doctor --provider corp       # конфиг, TLS, API, SQLite, исполняемые файлы MCP
```

`doctor` не создаёт БД и не запускает MCP; HTTP-проверка выполняет только GET models.
Показывает остаток срока клиентского сертификата и подсказки по исправлению ошибок.
Внутри REPL: `/connect NAME`, `/compact`, `/export FILE`, `/delete ID` (последняя требует
подтверждения и не удаляет текущую сессию; сначала /new). Экспорт пишется атомарно с 0600.
`/compact` сохраняет всю историю в SQLite и сокращает отправляемый контекст, в том числе
после единственного длинного хода. Последний запрос сохраняется целиком, исходная цель
подмешивается отдельно. Старые сообщения заменяются помеченными неполными выдержками;
это извлечение фрагментов, не полное семантическое резюме. Группы tool-call/result
не разрываются. Автосжатие работает перед каждым вызовом модели внутри цикла;
при слишком большом результате инструмента сокращается только его отправляемая копия.
Если последний запрос, инструкции и схемы сами не помещаются, агент сообщает об этом.

При --resume рабочая папка должна совпасть с сохранённой: ошибка показывает нужный --cwd.
ID и отпечаток адреса подключения защищают от неявной отправки истории другому провайдеру.
Терминальные управляющие последовательности из ответов удаляются; зарегистрированные секреты
маскируются. --json сохраняет машинный формат событий с маскированием известных секретов.

config show также показывает фактически выбранное подключение и источник модели из реестра провайдеров.

## OpenTUI

`gwagent tui install` устанавливает необязательный интерфейс в пользовательский кэш.
Запуск: `gwagent --tui`; обычный режим: `gwagent --plain`.
[Форматирование ответов, таблицы, управление и протокол](tui.md).
Выбор провайдера проверяет только локальные метаданные; ключ, TLS и список моделей проверяются
при первом сообщении или `/models`. Неверное имя сохраняет прежний выбор.

## Работа без модели

Интерактивный CLI открывает сессию без ключа, доступного API и выбранной модели.
`/help`, `/provider`, `/tools`, `/sessions`, `/new`, `/resume`, `/model`, `/export`, `/compact`
работают локально. Возобновление истории по-прежнему проверяет папку, ID и URL подключения,
но не требует его учётных данных. Модель можно выбрать позже через `/model NAME`.
Каталоги всех включённых провайдеров запрашиваются только через `/models`; при первом сообщении
без выбранной модели запрашивается каталог текущего подключения. К каталогу добавляются модели
с тегами из `tags` реестра (ядро помечает их, например `glm / glm-4.5-flash · free`), они
доступны для выбора даже если модель отсутствует в каталоге API.

`/connect NAME` для нового имени спрашивает URL API и необязательную модель, затем способ
авторизации и скрытый ключ/пароль. Подключение сохраняется как default и выбирается для новой
сессии без пробного LLM-запроса. Для существующего имени обновляются учётные данные;
URL меняется через `/provider set NAME URL [MODEL]`.
Первый `/connect` встроенного gateway использует URL из настроек пользователя.

Ошибка доступа/списка моделей относится к конкретному запросу: сообщение об ошибке подсказывает
`/connect`, `/provider`, `/model`, а редактор и команды остаются доступны.
Для ответа ассистента нужен доступный API; UI и настройка доступны без него.
Одноразовый `-p` сохраняет строгую проверку подключения и коды выхода.

## Меню команд и справка об инструментах

В [OpenTUI](tui.md) ввод `/` открывает список команд и включённых инструментов, в том числе MCP.
Фильтр работает по имени/описанию; ↑/↓ выбирают пункт, Enter открывает его, Tab подставляет,
Esc закрывает меню без потери текста. Команды с обязательными аргументами сначала дополняются
пробелом; после ввода аргументов Enter отправляет их обычным способом.

`/tools NAME` показывает описание, разрешение по умолчанию и JSON Schema параметров инструмента.
В TUI параметры представлены таблицей. Команда не запускает инструмент и доступна без модели.
Общий каталог `COMMANDS` и `App.command_catalog()` находится в `agent/cli.py`, метаданные
инструментов берутся из текущего `make_registry`, а не из отдельного списка интерфейса.

В OpenTUI `/models` открывает общий список «провайдер / модель»: текущая пара отмечена, ввод фильтрует
по имени, ↑/↓ и PageUp/PageDown выбирают, Enter переключает. Esc/Ctrl+C отменяют выбор.
При выборе другого провайдера создаётся новая сессия с сохранением прежней истории;
для того же провайдера меняется модель в текущей сессии. Default провайдера не меняется.
`/provider` открывает отдельный выбор подключения. В обычном `--plain` общий каталог
печатается с именами провайдеров; переключение — `/provider NAME`, затем `/model NAME`.

## Окна TUI и быстрые вызовы

F1/Ctrl+P — палитра команд, F2 — модели, F3 — провайдеры, F4 — сессии.
`/sessions` и `/resume` без ID открывают выбор с поиском; `/delete` без ID — выбор другой
сессии с последующим подтверждением (по умолчанию отмена).
`/tools` и `/mcp` открывают списки для просмотра параметров/состояния, инструменты не выполняются.
Системные сообщения отделены ролью и цветом, модели сгруппированы по провайдерам с цветными тегами.
[Управление, черновики и устройство окон](tui.md).

До переключения сессии проверяются папка и отпечаток подключения; ошибка проверки сохраняет
текущее подключение. Обычный `--plain` сохраняет текстовый ввод явных команд с ID.

## Делегация и журнал

`/agent задача` напрямую запускает инструмент `subagent` с отдельной историей;
делегация подчиняется обычным разрешениям и при необходимости спрашивает подтверждение.
Модель также может сама выбрать этот инструмент в обычном запросе.
`/logs [request_id]` выводит JSON-записи аудита текущей сессии с дочерними вызовами;
команда доступна без подключения к модели. `/export FILE` включает журнал метаданных.
ID создаётся ещё до настройки клиента; ошибка подключения получает собственный request_id
и запись request.failed. `--json` сохраняет reasoning и идентификаторы событий.
Раскрытие reasoning предусмотрено в OpenTUI; обычный текстовый режим его не печатает.

## Время ответа и `/revert`

После каждого ответа выводится приглушённая строка:
`Worked for 13m 39s • 19:25 • 21.7 ток/с`. Worked for показывает прошедшее время
пользовательской задачи до этого ответа; время окончания отображается в локальном часовом поясе,
скорость рассчитана по usage и времени самого вызова модели. Без usage скорость н/д.
Метрики включены в --json и экспорт, восстановление сессии сохраняет их.

`/revert` работает без модели. В OpenTUI открывает список ваших сообщений с поиском,
затем выбор: изменить сообщение, сохранив файлы, либо также откатить локальные файлы
с выбранного сообщения. Esc отменяет действие. Перед откатом проверяются снимки и
конфликты; недоступный режим не предлагается, причина объясняется. После выбора
исходный текст возвращается в редактор, отправка нового запроса остаётся за пользователем.
Старая ветка диалога архивируется, запросы старой ветки остаются в аудите.
В --plain команда спрашивает номер, режим и новый текст, затем отправляет его.
Имена сессий генерируются автоматически по первой задаче без запроса к API.

В меню режимы названы **«Исправить текст»** и **«Исправить текст и отменить все изменения»**.
Второй отменяет все локальные изменения модели с выбранного сообщения, включая последующие запросы и сабагентов.

В OpenTUI доступны Ctrl+A (выделить ввод), Ctrl+C (копировать выделение),
Ctrl+Shift+C (копировать выделение/весь черновик), Ctrl+Y (последний ответ целиком).
Без выделения Ctrl+C сохраняет отмену/выход. Для штатного выделения терминалом удерживайте
Shift при выделении мышью. По SSH копирование идёт через OSC 52, если это разрешено терминалом.

Запрос разрешения в OpenTUI управляется стрелками, Enter или левой кнопкой мыши.
Команда вынесена в отдельный прокручиваемый блок, область применения разрешения поясняется
рядом с выбором. Во время генерации можно редактировать следующий черновик стрелками;
Enter в OpenTUI отправляет его как уточнение текущему циклу без ожидания его завершения. Черновик переживает запрос разрешения.

Справа в OpenTUI отображаются заполнение контекста, цель, To do и статусы MCP, независимо
от текста ответа. На узком экране процент остаётся внизу. Цель/задачи обновляются инструментами
`goal`/`todo`, сохраняются между запусками и откатываются вместе с сообщениями. Детали —
[TUI](tui.md), [планирование](tools/planning.md). Щелчок по заголовку MCP открывает список серверов.

## Выбор активного агента

`/mode [build|plan]` показывает либо меняет активного агента без обращения к модели.
В OpenTUI переключение доступно через Tab в обычном редакторе. Оба агента используют общую
историю, цель и To do текущей сессии. Новая сессия начинается с build; открытая сессия
восстанавливает сохранённый режим. На время работы переключение Tab ставится в очередь
для следующего запроса. Команды настройки остаются доступны в обоих режимах.

build выполняет изменения с обычными правами. plan исследует проект и составляет план:
ему доступны чтение файлов/поиск, web_fetch/web_search, goal/todo и question; shell,
изменения файлов, произвольный http_request, MCP и делегация не доступны модели.
Вопросы модели поддерживаются в TUI и обычном интерактивном CLI, см. [question](tools/question.md).

В OpenTUI можно отправлять несколько уточнений через Enter во время работы модели.
Они вливаются в текущий цикл на безопасном шаге, не создавая параллельный запрос.
Ожидающие уточнения видны в ленте/счётчике и сохраняются в БД при отмене и закрытии.
После завершения Enter снова отправляет обычный новый запрос. Поздний отказ возвращает
текст в редактор. Слеш-команды во время работы не интерпретируются как уточнения.
Обычный синхронный --plain REPL сохраняет прежний ввод после завершения ответа.

Настройка из оболочки: `gwagent connect [имя]` (в том числе `--providers-file`, `--cwd`, `--settings`); внутри чата: `/connect [имя]`. На вопрос типа авторизации нажмите Enter для Bearer, затем введите ключ в скрытом поле. Если токен шлюза `gw-…` вставлен прямо в вопрос типа авторизации, он принимается как Bearer-ключ. EOF или Ctrl+C отменяют ввод без traceback и без замены сохранённых учётных данных.


### Мастер подключения

`/provider add [NAME]` добавляет, `/provider edit NAME` редактирует, `/connect [NAME]`
настраивает и выбирает подключение. Порядок: URL → способ подключения → скрытый API-ключ
либо PEM-сертификат, приватный ключ, CA и скрытый пароль ключа. Выбор модели — позже,
через `/models`. Все вопросы работают без модели. Enter сохраняет существующий URL;
сохранённый Bearer-ключ можно оставить пустым только для того же URL. Отмена до конца
мастера оставляет прежние данные. Команды `/provider enable|disable|remove NAME` управляют
старыми подключениями; удаление с подтверждением, для текущего/default сначала смените провайдера.
Из оболочки тот же мастер запускается через `gwagent connect NAME` или `gwproviders connect NAME`.
Подробнее: [провайдеры](providers.md#пошаговый-мастер-и-управление).


### Единый каталог данных

`GWAGENT_HOME=/srv/gwagent ./gwagent` использует один каталог для настроек, провайдеров,
секретов, доверия проектам, сессий и кэша TUI. По умолчанию — `~/.gwagent`.
`gwagent data` или `gwagent data show` печатает расположение файлов без их содержимого; в чате та же информация доступна через `/data`.
`gwagent data migrate` явно копирует старые файлы из ~/.config и ~/.local/share;
перед переносом закройте работающие CLI. Существующие файлы не перезаписываются.
Подробности и ограничения: [единое хранилище](data.md).
