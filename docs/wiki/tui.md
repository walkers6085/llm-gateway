# CLI на OpenTUI

Код: [`agent/tui.py`](../../agent/tui.py), [`agent/tui_backend.py`](../../agent/tui_backend.py),
[`tui/src/main.ts`](../../tui/src/main.ts), [`view.ts`](../../tui/src/view.ts),
[`format.ts`](../../tui/src/format.ts). Тесты: [`tests/test_tui.py`](../../tests/test_tui.py),
[`format.test.ts`](../../tui/src/format.test.ts), [`view.test.ts`](../../tui/src/view.test.ts).

## Установка и запуск

Необязательный интерфейс использует Bun >= 1.3.8 и @opentui/core 0.6.6.
Python остаётся исполнителем агента, инструментов, MCP и прав. Агентные фреймворки не добавлены.

```bash
# После установки Bun (https://bun.sh) и Python-пакета:
gwagent tui install
gwagent --tui --cwd ~/projects/demo
# Из checkout без pip install:
./gwagent tui install
./gwagent --tui
```

Установка копирует исходники интерфейса из checkout/установленного wheel в
`${XDG_CACHE_HOME:-~/.cache}/gwagent/tui/<hash>` и запускает
`bun install --frozen-lockfile --ignore-scripts`. Системные каталоги пакета не изменяются.
Хеш включает исходники и lockfile; после обновления пакета повторите `tui install`.
При запуске зависимостей из сети не устанавливается.
Для разработки: `bun install --cwd tui --frozen-lockfile --ignore-scripts`.

`gwagent` выбирает TUI автоматически при интерактивном stdin/stdout и установленных зависимостях;
иначе доступен обычный CLI. `--plain` принудительно выбирает обычный режим.
`-p` и `--json` сохраняют Python CLI; вместе с явным `--tui` они дают ошибку.
TUI требует терминал; в pipe используйте `-p ... --json`.
Все прежние параметры подключения, сессии, настроек и прав сохраняются.

## Представление ответов

- Markdown: заголовки, списки, выделение, блоки кода и GFM-таблицы.
- JSON-массив объектов преобразуется в таблицу с объединением полей; отсутствующие значения — `—`.
  Объект — таблица «Поле / Значение», массив скаляров — один столбец.
  Поддерживаются целиком JSON-ответы и завершённые блоки `json` внутри Markdown.
  Неоконченный/невалидный JSON остаётся текстом.
- «Важное» определяется по явным префиксам: `Важно:`, `Внимание:`, `Ошибка:`, `Итог:`,
  `Результат:`, их английским вариантам и пометкам `[!IMPORTANT]`, `[!WARNING]`,
  `[!CAUTION]`, `[!NOTE]`, `[!TIP]`. Внутри блоков кода пометки игнорируются.
  Это форматирование, без нового LLM-запроса и без изменения истории.
- Замечания подсвечены в ответе; при ширине от 100 колонок есть боковая панель.
  Ошибки инструментов и предупреждения также видны в панели.
- `/models`, `/provider`, `/sessions`, `/tools`, `/mcp` открывают общий компонент выбора.
  Параметры конкретного инструмента и данные ответов по-прежнему представлены таблицами.
  `/provider NAME`, `/connect`, `/resume`, `/compact`, `/export`, `/delete` используют тот же App.

Для защиты терминала удаляются ANSI/управляющие последовательности; активные Markdown-ссылки
ограничены HTTP/HTTPS. Код остаётся буквальным. JSON-таблица ограничена 100 строками,
12 столбцами и 2000 символами в ячейке; сокращение обозначается. Представление одного ответа
ограничено 128 Ki символов, на экране сохраняются последние 80 элементов.
История при подключении — последние 100 сообщений (до 512 KiB; сообщения/аргументы могут
сокращаться с предупреждением). SQLite хранит исходную историю; полный текст — `/export FILE`.

## Управление

| Клавиша | Действие |
|---|---|
| Enter / Shift+Enter | отправить / новая строка |
| Esc | во время работы — остановить текущий запрос; в меню — закрыть окно, в разрешении — отказ, в вопросе — пропуск |
| Ctrl+C | отменить запрос или диалог; в покое — выход |
| Ctrl+D | выход с завершением локального Python-процесса |
| Ctrl+R | исходный ответ / форматирование |
| Ctrl+O / щелчок по карточке | раскрыть инструменты / одну карточку |
| PageUp / PageDown, колесо | прокрутка истории |
| Y / N / A | разрешить один вызов / запретить / сохранить правило «всегда» в сессии |

Подтверждение не имеет автоматического выбора. Ввод ключа и пароля через `/connect` маскируется;
вставка тоже скрыта. Ответ диалога не попадает в историю сообщений. Учётные данные сохраняет
существующий [менеджер провайдеров](providers.md) в приватный `auth.json`.

## Локальный протокол

Bun запускает `${GWAGENT_PYTHON:-python3} -m agent.tui_backend`; Python launcher передаёт
свой интерпретатор и путь к установленному модулю. Рабочую папку определяет `--cwd`.
Постоянный subprocess сохраняет текущий App, сессию и подключения между командами.
stdin/stdout — JSONL, версия `1` в `ready`/`snapshot`; по stdout нет произвольных логов.
UI не выводит stderr дочернего процесса, ошибки приходят очищенными событиями.

Команды: `submit {text}`, `cancel`, `approve {id, decision: allow|deny|always}`,
`answer {id,value}`, `shutdown`. Пустые, неизвестные и слишком большие команды отклоняются.
Неверный JSON возвращает ошибку без выполнения; предел строки — 1 MiB.
Решения принимаются только для ожидающего ID; EOF/закрытие отменяет ожидающие подтверждения.

События цикла сохраняют [исходный формат](agent-loop.md); мост добавляет `snapshot`, `ready`,
`user`, `table {title,columns,rows}`, `input_request {id,prompt,secret}`, `notice`, `fatal`, `idle`.
`permission_request` отправляется после регистрации ожидающего Future, что исключает гонку ответа.
Закрытие UI сначала отправляет `shutdown`, затем при зависании — SIGTERM/SIGKILL с таймаутами.
При сбое backend интерфейс остаётся для чтения ошибки; Ctrl+D завершает его.

## Проверки

```bash
venv/bin/python -m pytest -q tests/test_tui.py
bun run --cwd tui typecheck
bun run --cwd tui test
```

Python-тесты запускают настоящий bridge против локального шлюза/mTLS-апстрима: поток, сессия,
таблицы, разрешение/отмена, продолжение после отмены, `/connect`, сохранение ключа без эха,
завершение процесса и launcher. Bun-тесты проверяют разбор и реальные нативные кадры OpenTUI,
узкий терминал, переключение исходника, решения подтверждения, скрытый ввод/вставку и карточки.

## Запуск без модели и настройка внутри чата

`ready` означает готовность интерфейса принимать ввод, а не доступность LLM.
Startup не читает ключ/сертификат и не запрашивает `/models`: без модели заголовок показывает
«модель не выбрана». Локальные команды и история доступны сразу.
Ошибки авторизации, TLS и сети при сообщении дают `error`/`idle`; при `/models` недоступные
провайдеры дают предупреждения, остальные каталоги продолжают отображаться,
сохраняя работающий backend и редактор. `fatal` остаётся для ошибок локального запуска/протокола.

```text
/connect my-provider
# URL API, модель (можно пропустить), bearer/basic/none, скрытый ключ
/models
/model model-name
```

Новый провайдер создаётся внутри диалога; успешный `/connect` сохраняет default и выбирает
его для новой сессии. Создание/изменение без ввода ключа:
`/provider add NAME URL [MODEL]`, `/provider set NAME URL [MODEL]`.
Выбор `/provider NAME` тоже не обращается в сеть и допускает отсутствие ключа/модели.
После успешной настройки можно отправлять сообщения в том же запущенном интерфейсе.

## Меню по `/`

В начале строки `/` сразу открывает меню «Команды и инструменты» над редактором.
Продолжайте вводить имя или часть описания: список фильтруется без запроса к модели.
Например, `/con` находит `/connect`, `/read` — справку инструмента `read_file`.

| Клавиша в меню | Действие |
|---|---|
| ↑ / ↓ | выбрать пункт, список прокручивается и замыкается |
| Enter | открыть команду; для обязательных аргументов подставить команду и пробел |
| Tab | только подставить команду, без отправки |
| Esc | закрыть меню, сохранив набранный текст |

После ввода аргументов Enter отправляет команду обычным способом. Если совпадений нет,
меню показывает подсказку. Меню не открывается внутри обычного сообщения, URL или многострочного
текста; скрыто во время работы, подтверждений и диалогов, включая ввод ключа.
Редактирование после Esc снова включает подсказки. В очень низком терминале (менее 16 строк)
остаётся обычный ввод.

Каталог поступает в поле `snapshot.catalog` из `App.command_catalog()`:
`kind`, `command`, `description`, `arguments` (`none`/`optional`/`required`), необязательные
`usage`, `name`, `permission`. В нём канонические команды, включённые встроенные инструменты
и загруженные MCP-инструменты; выключенные инструменты не предлагаются.

Пункт инструмента отправляет `/tools NAME` и показывает описание, разрешение по умолчанию
и таблицу параметров (тип, обязательность, описание). Это справка без выполнения инструмента;
запуск агентом сохраняет прежние проверки разрешений. Каталог и справка доступны без модели
и API-ключа. Подтверждения и секретные диалоги получают приоритет над клавишами меню.

## Все провайдеры и модели

`/models` запрашивает каталоги **всех включённых провайдеров** и открывает общий список
`провайдер / модель`. Одинаковые ID моделей у разных провайдеров остаются отдельными пунктами.
Текущая пара отмечена `●`; список прокручивается к ней. Поиск проверяет слова имени провайдера
и модели. ↑/↓ и PageUp/PageDown выбирают пункт, Tab/Shift+Tab переходят к следующему/предыдущему разделу,
Enter или щелчок выбирают, Esc/Ctrl+C отменяют.
Пустой результат поиска ничего не отправляет.

Запросы независимы, одновременно выполняются до четырёх, таймаут источника — 10 секунд.
Ошибки ключа, TLS, сети и пустой каталог дают предупреждение только для соответствующего
источника. Известные `models` и `model` из его конфига остаются с пометкой «из конфига,
API недоступен»; это не подтверждение доступности API. Отключённые провайдеры не запрашиваются.
Тегированные модели из `tags` реестра добавляются к каталогу с меткой (`API · free`);
недоступные сегодня у API модели (например, вне каталога `/models` free-варианты GLM)
остаются выбираемыми.
Кроме реестра включается gateway из настроек, если он текущий или у него есть токен.
Открытие каталога не меняет активное подключение и не запускает генерацию.

Выбор другой модели того же провайдера сохраняется в текущей сессии. Выбор **другого провайдера**
переключает подключение и модель вместе, создаёт новую сессию; прежняя история сохраняется
и доступна через `/sessions` и `/resume`. Подсказка перед выбором предупреждает о новой сессии.
Следующий запрос использует выбранную пару. Default провайдера не перезаписывается.

`/provider` тоже открывает список выбора: текущий провайдер отмечен, ввод фильтрует имена,
Enter переключает. Для этого не нужен ключ или доступная модель. Отключённые подключения
видны с меткой недоступности, но выбрать их нельзя. Явная команда `/provider NAME` по-прежнему работает.

Мост передаёт `table` с `selection.kind = model|provider`, `session_id`, текущим `provider`,
`current` (для модели) и `choices`. Модельный пункт содержит `provider` (имя либо null для
настроек gateway), `provider_name`, `model`, `available`; провайдерный — `provider`, `label`,
`model`, `enabled`. UI отправляет `select {kind, provider, model?, session_id}`.
Backend проверяет сессию и принадлежность пункта выданному списку, затем переключает атомарно
в рамках одной задачи и возвращает snapshot/idle. Старый или подменённый выбор отклоняется,
редактор остаётся доступен. При смене сессии открытый список закрывается.

## Единые окна и оформление

Все списки используют [`choice.ts`](../../tui/src/choice.ts): одинаковые стрелки,
PageUp/PageDown, поиск, мышь, подсветка текущего пункта, пропуск недоступных и прокрутка.
Разделы отделены заголовками с количеством пунктов. Модели сгруппированы по провайдерам,
`free` выделен зелёной плашкой и стоит первым внутри группы; остальные теги — синими плашками,
недоступный API — жёлтой. Теги участвуют в поиске. Длинные описания вынесены на отдельную строку.
Смена выделения обновляет существующие строки без пересоздания всего списка.

Системные сообщения имеют собственный фон и подписи `СИСТЕМА · ИНФО`, `ВНИМАНИЕ`, `ОШИБКА`.
Ответ ассистента остаётся карточкой «Агент», пользовательское сообщение — карточкой «Вы».
Служебное сообщение не добавляется в историю как ответ модели.

| Вызов | Окно |
|---|---|
| `/`, Ctrl+P, F1, `/help` | команды и инструменты |
| F2, `/models`, `/model` без имени | все модели по провайдерам |
| F3, `/provider` | подключения, включая видимые недоступные |
| F4, `/sessions`, `/resume` без ID | сохранённые сессии |
| `/delete` без ID | выбор другой сессии для удаления |
| `/tools` | встроенные и MCP-инструменты, Enter открывает параметры |
| `/mcp` | серверы; Enter открывает состояние и инструменты |

Горячий вызов и отмена окна сохраняют черновик сообщения. Нажатый до ready быстрый вызов
запоминается и открывает окно после завершения запуска. Палитра по Ctrl+P позволяет искать
без начального `/`. Tab в палитре только дополняет команду, в списках — меняет раздел.
Окна не перехватывают клавиши у запроса разрешения или ввода секрета.

Сессии показывают название, модель, провайдера, время изменения, папку и ID. Возобновление
восстанавливает историю без запроса к модели. Сессии другой папки видны, но недоступны для
выбора: их открывают с нужным `--cwd`. В списке до 200 последних сессий и текущая, если она
старше этого диапазона. Другие владельцы не попадают в список.
Удаление требует второго подтверждения; первый пункт — «Отмена», текущую сессию удалить нельзя.
Backend проверяет принадлежность выданному списку, владельца и актуальную исходную сессию.

Авторизация Bearer/Basic/none и подтверждение удаления представлены тем же списком.
Текстовые поля и секреты имеют выделенную подпись диалога. Esc/Ctrl+C отменяют диалог и
очищают временный секрет; в запросе разрешения Esc означает отказ. Ввод ключей и вставка
по-прежнему маскируются.

## Как изменять интерфейс

- [`theme.ts`](../../tui/src/theme.ts): палитра, цвета ролей и плашек. Ключи и сеть здесь не используются.
- [`menus.ts`](../../tui/src/menus.ts): `menuSpecs` — заголовок, поиск, пустое состояние и действие;
  `menuShortcuts` — горячие вызовы; `createPicker` — адаптер данных в общие пункты выбора.
- [`choice.ts`](../../tui/src/choice.ts): только отрисовка списка, группы, метки, прокрутка и мышь.
- [`view.ts`](../../tui/src/view.ts): переключение состояний, черновики и приоритет клавиатуры.
- [`agent/tui_backend.py`](../../agent/tui_backend.py): данные и проверка действий, а не цвета/раскладка.

Чтобы добавить список, опишите его в `menuSpecs` и адаптере `createPicker`, передайте
`table.selection` с `kind`, `choices` и `session_id`, добавьте безопасное действие на backend.
Стрелки, поиск, Tab, мышь, Esc и оформление повторно реализовывать не нужно.
Для сессий протокол использует `select {kind: session|session-delete, target, session_id}`.
Для выбора Bearer/Basic/none и подтверждения удаления `input_request.choices` содержит
`value`, `label`, необязательные `description` и `danger`; ответ сохраняет прежний `answer`.

## Компактные уведомления, reasoning и ход работы

Системные сообщения и ошибки отображаются одной приглушённой строкой с отдельным
символом и подписью роли, без яркой рамки и большого блока. Длинная диагностика
раскрывается кликом или `Ctrl+E` (все системные подробности).
Reasoning провайдера из событий `reasoning` показывается свёрнутым блоком с числом
символов; клик раскрывает один блок, `Ctrl+T` переключает все. История восстанавливает
`reasoning_content`. JSONL snapshot ограничивает размер reasoning, как и обычный текст.

Индикатор занимает две строки во время работы: анимированные точки, этап (рассуждения,
ответ, инструмент, сабагент), прошедшие секунды, ID запроса и Esc / Ctrl+C для отмены.
На подтверждениях анимация не перекрывает диалог; после завершения таймер освобождается.
`/agent задача` есть в меню команд, а дочерняя задача получает отдельную карточку результата.
Таймеры очищаются при закрытии интерфейса.

Ошибки инструментов сохраняют компактную карточку с приглушённой меткой: полный вывод
не раскрывается автоматически и доступен кликом или Ctrl+O.

## Время, название сессии и возврат к сообщению

Под каждым ответом есть `Worked for … • HH:MM • … ток/с`; формат сохраняется при
Ctrl+R и повторном открытии истории. Метрики детей показываются в карточке сабагента.
Название текущей сессии отображается в заголовке вместе с моделью и ID.
Общий реестр `menus.ts` включает окно `revert`: поиск по пользовательским сообщениям,
стрелки, Enter, Esc и мышь работают как в других окнах.

После `/revert` выбирается сообщение, затем режим: сохранить файлы или откатить их.
Доступность второго режима проверяется до предложения выбора, количество затронутых
записей видно в описании. Затем `draft` возвращает исходный текст в поле ввода;
история обновляется snapshot. Отмена диалога сохраняет черновик и историю.
Событие draft не отправляет сообщение автоматически.

В меню режимы названы **«Исправить текст»** и **«Исправить текст и отменить все изменения»**.
Второй отменяет все локальные изменения модели с выбранного сообщения, включая последующие запросы и сабагентов.

## Служебные ответы терминала и копирование

`terminal-input.ts` собирает OSC/DCS/APC-ответы на входе **до** парсера OpenTUI, включая
пакеты с задержками SSH. Ответ о цвете `ESC ] 12;rgb:7979/b8b8/ffff ST` раньше после
таймаута парсера оставлял в редакторе `:7979/b8b8/ffff`. Это RGB синего `#79b8ff`, а не
содержимое сессии. Полный ответ передаётся штатному обработчику терминальных протоколов;
оборванный/переполненный ответ не превращается в пользовательский текст. Предел — 64 КиБ,
после 3 секунд ответ отбрасывается до терминатора; Ctrl+C/Ctrl+D освобождают ввод.
Bracketed paste проходит буквально: обычный текст, похожий на RGB, не удаляется.
Поток подключается до createCliRenderer, закрывается после renderer.closed; raw mode
настоящего stdin восстанавливается штатным renderer через обёртку.

- `Ctrl+A` — выделить весь текст редактора; Shift+стрелки — частичное выделение.
- Выделение мышью + `Ctrl+C` — копировать текст из ввода или вывода.
- `Ctrl+Shift+C` — копировать выделение; без выделения — черновик активного редактора
  либо последний ответ. Некоторые терминалы обрабатывают эту комбинацию самостоятельно.
- `Ctrl+Y` — копировать последний ответ полностью, включая Markdown-исходник.
- Без выделения Ctrl+C по-прежнему отменяет запрос/диалог или завершает CLI.
- Shift + выделение мышью использует выделение самого терминала, обходя mouse capture.

Буфер обслуживает уже установленный OpenTUI: локальный clipboard и OSC 52 для терминала,
в том числе SSH. Новые библиотеки не добавляются. Статус «Копирование отправлено в терминал»
означает отправку OSC 52: разрешение на clipboard зависит от настроек терминала/tmux.
Ошибка/отсутствие поддержки показываются без ложного подтверждения копирования.
Маскированный ввод ключа/пароля не копируется. Clipboard-сервис закрывается вместе с UI.

Карточки системных сообщений, reasoning и инструментов раскрываются только за заголовок:
выделение текста тела больше не сворачивает карточку. Markdown-текст рисуется и до готовности
подсветки синтаксиса, чтобы обычный ответ не исчезал и был доступен для выделения.

## Понятные запросы разрешения и стрелки редактора

`approval.ts` содержит отдельный `ApprovalPanel`: спокойная рамка, описание действия,
причина подтверждения и точный текст команды в отдельном блоке «Команда». Длинный текст
не обрезается: используется прокрутка мышью или PageUp/PageDown. Для файлов показаны
путь и «Было / Станет», для сабагента — задача, для HTTP — метод, URL, заголовки и тело.

Варианты без ярких цветных плашек:

- **Не разрешать** — пропустить действие, агент продолжит диалог. Выбрано изначально.
- **Разрешить один раз** — выполнить только текущий вызов.
- **Разрешать в этой сессии** — сохранить конкретное правило; само правило показано при выборе.

↑/↓, ←/→ и Tab/Shift+Tab меняют вариант; Enter подтверждает; левая кнопка мыши выбирает
ответ. Правая кнопка не подтверждает действие. Esc/N — отказ, Y — один раз, A — правило сессии.
На низком экране отображаются все три варианта без дополнительных строк описаний.
Команда и её параметры остаются доступными для выделения/копирования.
`ChoiceList` поддерживает необязательный quiet-режим, не меняющий оформление остальных меню.

Редактор поддерживает ←/→, ↑/↓ между строками, Home/End и выделение Shift+стрелками.
Во время ответа модели можно готовить и редактировать уточнение; Enter отправляет его
в текущий цикл на ближайшей безопасной границе шага. На время запроса разрешения редактор теряет фокус, стрелки
управляют ответами, вставка блокируется; существующий черновик сохраняется.
Обычные меню перехватывают только свои клавиши; Shift+стрелки остаются у поля поиска.
`terminal-input.ts` собирает CSI и SS3 последовательности стрелок до передачи парсеру,
включая SSH-пакеты с задержками, чтобы хвосты A/B/C/D не становились обычным текстом.

После ответа мышью фокус сразу возвращается в редактор. Если запрос разрешения завершился
по таймауту, панель закрывается по результату инструмента и черновик снова доступен.

## Правая панель сессии

`sidebar.ts` показывает контекст, цель, To do, MCP и замечания из ответа независимыми
блоками. Поток ответа и разбор важных фрагментов больше не заменяют содержимое панели.
Панель прокручивается мышью; при ширине меньше 100 колонок скрывается, процент контекста
остаётся в нижней строке. Щелчок по заголовку MCP открывает `/mcp`, сохраняя черновик.
Во время выполнения запроса открытие меню блокируется как и остальные меню.

Контекст: текущий вход / `max_input_tokens` профиля модели (либо общих настроек), процент
и полоса заполнения, отдельно резерв `max_output_tokens`. Это консервативная оценка по UTF-8
байтам JSON, включая системный текст, цель/план и спецификации инструментов, а не точный
токенизатор модели. Размер аппаратного окна провайдера автоматически не определяется.
После сжатия показатель уменьшается; переполнение отображается выше 100%, полоса ограничена.
Реальный `prompt_tokens` последнего вызова показан отдельно при наличии usage;
это не накопленный расход сессии. При переключении сессии значение сбрасывается.

JSONL snapshot и событие `dashboard` содержат session_id, planning, context и mcp.
Событие `context` ядра показывает реально подготовленный вход до каждого вызова модели,
включая повтор после переполнения. Snapshot/опрос панели не запускает сжатие и не вызывает
модель. Статус планирования обновляется после результата инструмента, MCP — также раз в
две секунды локальной проверкой состояния, без дополнительных сетевых запросов.
Все фоновые задачи опроса закрываются вместе с мостом.

Задачи отмечаются ○ (ожидает), ◉ (в работе), ✓ (готово), – (отменена).
Цель и план сохраняются через [инструменты планирования](tools/planning.md).
MCP показывает подключённые серверы, число инструментов, ошибки соединения и выключенные
конфигурации. Для HTTP это последнее известное состояние, без активного health-check.

Длинная цель и список задач по умолчанию сокращены в панели: нажмите соответствующий
заголовок для полного текста/списка, повторный щелчок сворачивает его. Текст под заголовками
можно выделять без переключения состояния. Раскрытие сбрасывается при смене сессии.
В свёрнутом списке первыми показаны пункты в работе и ожидающие; полный список сохраняет
исходный порядок модели.

## Агенты build и plan, Tab и вопросы

В обычном поле ввода Tab/Shift+Tab переключает build ↔ plan, сохраняя текст и позицию
редактора. Индикатор активного агента находится в заголовке и нижней строке; карточки
ответов подписаны build/plan, в том числе после открытия истории. В меню Tab по-прежнему
подставляет команду/меняет раздел, в разрешениях и вопросах — меняет вариант ответа.
Внутри диалога Tab не переключает агента. Смена не вызывает модель и не создаёт сессию.

JSONL-команда set_agent содержит mode=build|plan. Когда запрос работает, мост ставит режим
в очередь и сообщает agent_mode с mode и next_mode. Права текущего запроса не меняются;
очередь применяется после завершения/отмены. Если сессия сменилась, очередь старой сессии
сбрасывается. Snapshot содержит session.agent_mode и next_agent_mode.

Модель вызывает [question](tools/question.md), мост показывает input_request с question=true,
agent, allow_custom и необязательными choices. Последний пункт позволяет перейти к свободному
ответу; Enter отправляет его, Esc пропускает вопрос. Ответ type=answer с value=null и
cancelled=true допустим только для вопроса. Остальные диалоги по-прежнему принимают строки.
Закрытие или таймаут передаётся input_closed с id. Вопрос сохраняет следующий черновик,
после ответа восстанавливает ввод сразу, пока модель продолжает работать.

## Уточнение работающему агенту

Enter в обычном редакторе во время работы отправляет JSONL-команду steer с уникальным id
и text. Это продолжение текущего цикла, а не новый submit; таймер, расход, выбранный агент
и очередь переключения build/plan сохраняются. Текст очищается после отправки, можно писать
следующее уточнение. Команды со слешем остаются в редакторе до завершения; разрешения и
вопросы используют собственные диалоги как прежде.

Мост подтверждает запись в SQLite событием input_queued. В ленте появляется карточка
«уточнение ожидает безопасного шага», внизу — счётчик. input_applied меняет заголовок на
«учтено» без повторного добавления текста, input_rejected помечает блокировку хуком.
Snapshot/dashboard включают pending_inputs, чтобы очередь восстанавливалась при открытии
сессии. Если цикл уже закрылся или очередь заполнена, steering_rejected возвращает текст
в редактор, сохраняя уже набранный следующий текст (либо черновик под открытым диалогом).

Текущий HTTP-вызов модели и уже запущенный инструмент завершаются штатно. Уточнение попадает
в следующий вызов модели в том же цикле; оставшиеся ещё не начатые инструменты старой пачки
пропускаются с полноценными tool-результатами. Ожидать завершения всего агентского цикла
не требуется. Во время вопроса/разрешения сначала завершите или пропустите диалог.

Esc в основном окне отменяет текущую генерацию и выполняемый инструмент через общий механизм отмены. Сессия и история сохраняются, набранный черновик остаётся в редакторе. В покое Esc не завершает CLI.

Настройка из оболочки: `gwagent connect [имя]` (в том числе `--providers-file`, `--cwd`, `--settings`); внутри чата: `/connect [имя]`. На вопрос типа авторизации нажмите Enter для Bearer, затем введите ключ в скрытом поле. Если токен шлюза `gw-…` вставлен прямо в вопрос типа авторизации, он принимается как Bearer-ключ. EOF или Ctrl+C отменяют ввод без traceback и без замены сохранённых учётных данных.

Совместимость с Bun 1.3.8 проверена установкой с frozen-lockfile и полным набором тестов TUI на Linux x86_64. Сам @opentui/core 0.6.6 объявляет минимум 1.3.14; проект дополнительно проверяет используемые им функции на 1.3.8. CI запускает проверки на обеих версиях. Версия dev-пакета @types/bun не задаёт минимальную версию исполняемого Bun.


### Управление провайдерами

Окно `/provider` (F3) содержит раздел «Управление»: добавить провайдера, изменить существующий,
включить/отключить и удалить с подтверждением. Действия доступны через поиск, стрелки и мышь,
в том числе редактирование отключённого подключения. Добавление последовательно запрашивает
имя → URL → тип подключения → ключ или сертификат; редактирование начинает с URL.
Секретные поля скрыты, сертификат и пути вводятся обычными полями; mTLS есть в списке типов.
Esc/Ctrl+C отменяют мастер без частично сохранённых настроек. Смена URL требует заново
ввести ключ, Enter для старого ключа разрешён только на прежнем URL. Настроенный провайдер
выбирается и включается, затем модель выбирается через `/models`. Удаление и отключение
текущего/default запрещены до выбора другого подключения.
Реализация: `agent/providers.py` (единый мастер), `agent/cli.py` (команды),
`agent/tui_backend.py` (диалоги и действия), `tui/src/menus.ts` (общие списки и команды).
