# Устойчивые запросы и очистка контекста

Код: `agent/compaction.py`, `agent/retry.py`, `agent/context.py`, `agent/llm.py`, `agent/loop.py`, `agent/mcp.py`.
Тесты: `tests/test_retry_cleanup.py`, `tests/test_llm.py`, `tests/test_loop.py`, `tests/test_mcp.py`.

## Повторы временных ошибок

HTTP 408, 429, 500, 502, 503, 504 и сетевые обрывы до начала ответа повторяются с backoff.
Стандартные error.code/status в SSE также распознаются, в том числе rate_limit_exceeded
и overloaded_error. Для каждой модели/шага по умолчанию разрешено пять повторов
после первой попытки: 2, 4, 8, 16, 32 секунды плюс небольшой случайный сдвиг до 20%.
Обычный backoff ограничен 60 секундами; общий срок назначения повторов — 180 секундами.
Это не общий таймаут HTTP-попытки: длительность самого запроса ограничивает HTTP-клиент.

Retry-After в секундах или формате HTTP-даты задаёт минимальное ожидание. Его не сокращают
до max_delay: если ожидание выходит за max_elapsed, автоматический повтор не назначается.
Нельзя ждать меньше разрешённого провайдером. Постоянные 400/401/403, ошибки формата ответа
и уже начавшийся вывод текста/reasoning автоматически не переигрываются. Переполнение
контекста по-прежнему имеет одну отдельную попытку после сжатия, без сброса токен-бюджета.

Ожидание использует asyncio.sleep, отменяется Esc/Ctrl+C и не удерживает модельный семафор.
Уточнения, принятые во время ожидания, подмешиваются перед повтором. HTTP-запрос модели
повторяется внутри того же хода: выполненные инструменты и MCP-вызовы заново не запускаются.
После исчерпания попыток текущий ход завершается ошибкой, а сессия, история и команды
остаются доступны. Каталог /models и сами инструменты этим механизмом не повторяются.
В -p режиме после исчерпания попыток CLI по-прежнему возвращает ненулевой код.

У каждой HTTP-попытки отдельный span с общим request_id. Событие model.retry содержит
номер повтора, HTTP-статус, задержку и failed_span_id. События model.start/end остаются
для всех попыток, в том числе неуспешных. В TUI отображаются статус ожидания и обратный
отсчёт; warning.retry доступен также потребителям JSON/SSE.

Настройки: [model_retry](settings.md#повторы-и-очистка-контекста).

## Очистка отправляемого контекста

Очищается только копия tool-сообщений перед оценкой размера и отправкой модели.
Сохранённые сообщения, события инструментов и их журнал не переписываются; обычные
лимиты вывода и редактирование секретов продолжают работать как прежде.

- Удаляются ANSI/CSI, OSC/DCS/APC/PM, в том числе незавершённые последовательности,
  NUL и другие управляющие коды. CRLF и CR нормализуются в LF.
- JSON-объекты и массивы уплотняются без изменения строк, точности чисел, порядка
  и повторяющихся элементов/ключей: удаляется только whitespace вне JSON-строк.
- Избыточные пустые строки сводятся к одной пустой строке. В fenced code это не применяется.
- Повторяющиеся обычные строки можно сжать с явным указанием исходного количества;
  опция выключена по умолчанию. Для JSON и fenced code она не применяется.
- Результаты встроенных read_file/edit_file/write_file полностью сохраняют формат.
  Код и пользовательские/system/assistant-сообщения, reasoning, tool_calls, их аргументы
  и все соответствующие tool_call_id не удаляются.

Удаление выполненных вызовов из истории нарушило бы протокол и скрывало уже совершённые
действия, поэтому этот механизм их не вырезает. Старые группы по-прежнему сокращаются
штатным механизмом контекста, а полный журнал остаётся в SQLite.
Очистка не является защитой от prompt injection и не переинтерпретирует смысл внешнего текста.

MCP render_result сохраняет уникальный structuredContent даже при наличии текстового
резюме. Если текст уже содержит семантически тот же JSON, второе представление не добавляется.
Изображения/аудио и двоичные ресурсы по-прежнему представлены текстовыми метаданными,
бинарные данные не разворачиваются в промпт.

Событие журнала context.cleaned содержит размеры до/после и число изменённых результатов,
без содержимого инструментов. Настройки: [context_cleanup](settings.md#повторы-и-очистка-контекста).

## Сводка через модель

`/compact`, автокомпакт и восстановление после переполнения вызывают текущую модель
без инструментов. История передаётся как недоверенные данные с предыдущей сводкой;
длинный вход обрабатывается частями с последовательным обновлением сводки. Размер
каждого запроса ограничен окном модели, выход — context_compaction.max_output_tokens.
Сохраняются цель, ограничения, решения, пути изменённых файлов, результаты и незавершённые
задачи. Последний пользовательский запрос и целые недавние пары tool_calls/tool остаются
в активном контексте; цель и todo дополнительно подмешиваются основным циклом.

Расход сводки входит в общий max_turn_tokens и серверный учёт; model.start/end имеют
purpose=compaction на model.start, отдельный span и общий request_id текущего хода.
Ручной /compact получает отдельный request_id, не добавляя искусственную реплику пользователя.
При ошибке, таймауте, отсутствии модели, слишком маленьком окне или бюджете используется
локальное сжатие; событие context.compaction_fallback содержит тип причины без текста.
Автоматических повторов запроса сводки нет: резервный механизм позволяет быстрее продолжить.
Esc отменяет суммаризацию без обновления сводки/границы. Результат применяется транзакционно
только к неизменившейся истории; исходные сообщения и результаты не удаляются.

## Определение размеров контекста

agent/model_limits.py объединяет лимиты модели для основного цикла, панели и суммаризации.
Обнаружение /models читает context_window/context_length/max_context_length/max_model_len
и limit.context, limits, top_provider, а также лимиты выхода и aliases. В памяти сохраняются
только числовые метаданные; каталоги отдельных подключений не смешиваются. Подключение
проверяет каталог с таймаутом 5 секунд, его ошибка не блокирует запрос модели. /models
обновляет каталог; перезапуск или новое подключение повторяет обнаружение.

Окно и бюджет хода независимы: бюджет по умолчанию автоматически растёт с окном модели.
Оценка токенов использует ceil(байты JSON / 3) + 64, а не равенство байт токенам.
Без настоящего токенизатора она остаётся приблизительной. Источники паспортных значений:
[GLM-4.5](https://docs.z.ai/guides/llm/glm-4.5),
[GLM-4.7](https://docs.z.ai/guides/llm/glm-4.7),
[GLM-5.1](https://docs.z.ai/guides/llm/glm-5.1). Метаданные конкретного API важнее каталога.
Формат max_context_length описан в [API Mistral](https://docs.mistral.ai/api/endpoint/models).
