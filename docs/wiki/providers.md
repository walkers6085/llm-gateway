# Провайдеры и учётные данные

Общий механизм `agent/providers.py` используется [CLI](cli.md), каталогом моделей,
[бенчмарками](bench/README.md) и диагностикой. Поддерживается OpenAI-совместимый
chat/completions, Bearer, Basic и mTLS. Нативные протоколы других API не преобразуются.

## Быстрый старт

После установки доступны `gwproviders`, `gwagent`, `gwbench`. Из checkout можно использовать
`venv/bin/python -m agent.providers`, `./gwagent`, `venv/bin/python -m bench`.

```bash
gwproviders add corp --url https://llm.example.org/v1 --model MODEL \
  --cert /path/client.crt --key /path/client.key --ca /path/ca.pem
gwproviders connect corp
gwproviders models corp
gwproviders use corp
gwagent
gwbench --provider corp --suites tools,structured,chain --quick
```

`connect` сначала спрашивает URL, затем способ подключения и ключ либо сертификат; секреты вводятся скрыто.
Пароль зашифрованного TLS-ключа также вводится скрыто. В интерактивном агенте — `/connect NAME`,
затем `/provider NAME` для новой сессии. Ключи не передаются аргументами командной строки.

## Готовые подключения

В новом реестре сразу доступны пресеты (ключей в коде нет):

| Имя | API | Модель | Переменная для auth=env |
|---|---|---|---|
| `gateway` | `http://127.0.0.1:7700/v1` | выбрать через `/model` или `/models` | `GW_TOKEN` |
| `glm` | `https://api.z.ai/api/paas/v4` | `glm-5.1` | `ZAI_API_KEY` |
| `mistral` | `https://api.mistral.ai/v1` | `mistral-small-latest` | `MISTRAL_API_KEY` |

`/connect glm` или `/connect mistral` сохраняет ключ в auth.json и переключает провайдер
на stored: переменная окружения после этого не нужна. В открытом CLI переключение —
`/provider glm` или `/provider mistral`. Для сохранения default вне чата:
`gwproviders use glm` или `gwproviders use mistral`.

Пресеты не выполняют сетевых запросов при запуске и не меняют существующий пользовательский
реестр. Если реестр создан до появления пресетов, добавьте подключение через
`/provider add NAME URL MODEL`, затем `/connect NAME`.
Модель можно сменить через `/model NAME`; актуальный каталог запрашивается командой `/models`.
Серверные ключи импортируются только в пользовательский auth.json, а не в репозиторий.

## Хранение

- `~/.gwagent/providers.json`: URL, стабильный `id`, модель, `token_env`, настройки TLS,
  справочный список `models`, необязательные теги `tags`, флаг `enabled` и `options` возможностей API.
- `~/.gwagent/auth.json`: секреты по стабильному ID подключения; `agent/credentials.py`.
- При нестандартном `--file FILE` auth.json находится рядом с ним. Потребители принимают
  `--providers-file FILE`.
- Запись атомарная с fsync, блокировкой и правами 0600. Новые каталоги создаются с 0700;
  права существующего каталога проверьте отдельно. Auth.json с правами шире 0600 или
  симлинк вместо него отклоняется. Это защита правами ОС, не шифрование.
- Сертификаты и приватные ключи остаются отдельными файлами; относительные пути считаются
  от каталога providers.json. Содержимое ключей в JSON не копируется.

```json
{
  "default": "corp",
  "selected": true,
  "providers": {
    "corp": {
      "id": "stable-connection-id",
      "url": "https://llm.example.org/v1",
      "token_env": "",
      "auth": "stored",
      "model": "MODEL",
      "models": [],
      "tags": {"MODEL": ["free"]},
      "enabled": true,
      "tls": {"cert": "/path/client.crt", "key": "/path/client.key", "ca": "/path/ca.pem"},
      "options": {"stream": true, "tools": true, "temperature": true, "usage": true, "max_tokens_field": "max_tokens"}
    }
  }
}
```

Режим `auth=env` использует только переменную `token_env`; её отсутствие вызывает ошибку,
без переключения на другой источник. `auth=stored` использует только auth.json, `auth=none`
не посылает авторизацию. Старые записи без auth работают как раньше: env, если задан token_env,
иначе none. `connect` переключает запись в stored. Учётные данные Basic не подставляются в URL.
Сохранённые учётные данные также привязаны к отпечатку URL: после его изменения нужен connect.
TLS всегда проверяет сертификат сервера; опции отключения проверки нет.

## Управление и совместимость

`list`, `add`, `update`, `remove`, `use`, `connect`, `disable`, `enable`, `models`.
`update` принимает `--url`, `--model`, `--models`, `--token-env`, `--tag`, `--cert`, `--key`, `--ca`.
Для удаления старых TLS-полей или изменения options отредактируйте JSON, сохраняя id.

Теги моделей (`tags`) — «модель → список меток», информационные: не allowlist и не влияют на
запросы. Их удобно ставить по итогам проверки моделей, например `free` для отвечающих на
chat/completions. CLI: `add ... --tag MODEL=TAG1,TAG2` и `update NAME --tag MODEL=TAG` (повторяемая,
метки сливаются с существующими). `list` показывает метки: `модель(тег); …`. Для полного удаления
или правки отредактируйте JSON. Схема проверяет, что это объект с массивами непустых строк.
Изменение token_env само по себе не меняет явно выбранный auth: для env укажите этот режим
в JSON. `remove` удаляет и запись секретов; default сначала смените через use.

`add` не активирует новое подключение и не меняет старые настройки gateway. Для этого нужен
явный `use` (`selected=true`). Реестры предыдущей версии без selected сохраняют прежнюю
семантику выбранного default. `--provider` и явный `--providers-file` работают независимо от selected.
Ошибка записи возвращает объект менеджера к предыдущему сохранённому состоянию; параллельное
изменение файла другим процессом обнаруживается и требует повторного чтения.

Возобновляемая сессия проверяет ID и отпечаток URL. Удаление/повторное создание записи с тем же
именем или изменение URL не отправляет старую историю на новое назначение. Для старых сессий
без отпечатка действует прежняя привязка по имени: создайте новую для строгой проверки.

`models` вызывает GET models относительно URL API; его тело ошибки не выводится. `models` в
конфигурации — справочный список, не allowlist. `--model` переопределяет модель. При пустой
модели агент выбирает первую из API, бенчмарк требует явную модель/default в записи.

Ключи, прочитанные механизмом credentials, маскируются в событиях, новых сообщениях истории,
выводе CLI и сохраняемых отчётах. Файлы auth/TLS запрещены файловым инструментам.
Это не песочница: разрешённая shell-команда или доверенный MCP работают с правами пользователя.
Ранее сохранённые истории автоматически не очищаются.

Проверки: `tests/test_providers.py`, `tests/test_provider_sessions.py`, `tests/test_hardening.py`.
Последний содержит настоящий mTLS-handshake CLI-клиента/бенчмарка с локальным апстримом.

## Настройка из интерактивного CLI/TUI

Ключ и работающая модель не требуются для открытия интерфейса.
`/connect NAME` создаёт новое подключение (URL, необязательная модель), запрашивает авторизацию
и сохраняет default. Для существующего имени команда обновляет секреты.
`/provider add NAME URL [MODEL]` и `/provider set NAME URL [MODEL]` меняют метаданные без сети;
`/provider NAME` выбирает подключение для новой сессии без проверки ключа или `/models`.
После изменения URL активного подключения история остаётся в старой сессии; новая привязана
к новому URL. Секреты по-прежнему связаны с хешем адреса, поэтому для нового URL нужен `/connect`.
Подробнее: [CLI без модели](cli.md), [OpenTUI](tui.md).

## Общий каталог и выбор в TUI

`/models` собирает модели всех включённых провайдеров, показывает пары «провайдер / модель»
и переключает оба значения при выборе. Дубликаты ID разных провайдеров сохраняются.
К каталогу добавляются модели из `tags` реестра с показом метки — так выбор видит проверенные
вручную модели (например `free`), которых нет в каталоге API. Для недоступных API известные
модели из конфига помечаются как неподтверждённые; другие источники остаются доступны.
`/provider` открывает выбор подключения без запроса к модели.
Другой провайдер означает новую сессию, старая история сохраняется. [Управление](tui.md).

## GLM Flash вне каталога API

Пресет `glm` явно содержит `glm-4.5-flash` и `glm-4.7-flash` в `models` и в
`tags` с меткой `free`. Они предлагаются в общем выборе даже когда отсутствуют в ответе
провайдера на `/models`. Для существующих реестров добавьте `--tag glm-4.5-flash=free`
и `--tag glm-4.7-flash=free` через `gwproviders update glm`.

На этом сервере 2026-10-19 проверены только эти два ID: оба вернули HTTP 200 и ответ
через chat/completions. Метка `free` соответствует их строкам в
[официальном тарифе Z.AI](https://docs.z.ai/guides/overview/pricing);
успешный HTTP-ответ сам по себе не доказывает бесплатность других моделей.

Настройка из оболочки: `gwagent connect [имя]` (в том числе `--providers-file`, `--cwd`, `--settings`); внутри чата: `/connect [имя]`. На вопрос типа авторизации нажмите Enter для Bearer, затем введите ключ в скрытом поле. Если токен шлюза `gw-…` вставлен прямо в вопрос типа авторизации, он принимается как Bearer-ключ. EOF или Ctrl+C отменяют ввод без traceback и без замены сохранённых учётных данных.


## Пошаговый мастер и управление

`gwagent connect NAME`, `gwproviders connect NAME`, `/connect NAME` и `/provider edit NAME`
используют один мастер. В TUI `/provider` (F3) содержит выбор подключения и раздел
«Управление»: добавить, изменить, включить/отключить, удалить. `/provider add [NAME]`
запрашивает имя, если его нет; существующее имя требует явного редактирования.

1. URL API. Для существующего подключения Enter сохраняет адрес. `/v1` не добавляется
   автоматически: например, API GLM использует `/api/paas/v4`.
2. Способ подключения: Bearer (ключ), mTLS (клиентский сертификат), Basic или без авторизации.
3. Bearer: скрытый ввод ключа. При неизменном URL Enter сохраняет прежний сохранённый
   Bearer-ключ. Для нового URL нужен новый явный ввод ключа; перенос секрета молча запрещён.
4. mTLS: сертификат PEM → приватный ключ PEM (может находиться в том же файле) → CA
   (необязательно, иначе системные CA) → скрытый пароль приватного ключа (необязательно).
   HTTPS обязателен. Пути вводятся на машине, где запущен CLI, относительные считаются
   от папки providers.json. Файлы и пара сертификат/ключ проверяются локально до сохранения,
   сетевой запрос не выполняется. Для существующих путей Enter сохраняет значение, `-` убирает его.

Модель выбирается после настройки через `/models`; она не прерывает ввод URL и ключа.
Добавление и /connect сохраняют запись и секреты после полного ввода и проверки, выбирают подключение
по умолчанию и включают его. /provider edit другого провайдера сохраняет текущее подключение, default
и состояние enabled. Редактирование активного подключения создаёт новую сессию. Отмена не создаёт пустого провайдера и не меняет старые данные.
При ошибке записи реестра прежние учётные данные восстанавливаются. Это согласованное
обновление двух файлов при обычных ошибках записи, а не транзакция с гарантией при отключении питания.
Секреты остаются в auth.json (0600), файлы PEM в реестр не копируются.
Выбор Bearer/Basic/none снимает прежний mTLS; для сочетания mTLS и Bearer используйте
явную настройку tls и `connect` через Python API либо реестр, как описано выше.

`/provider enable NAME`, `/provider disable NAME`, `/provider remove NAME` управляют
существующими записями. Удаление требует подтверждения и убирает сохранённые ключи;
сами PEM-файлы и история сессий остаются. Текущий провайдер и default нельзя удалить
или отключить: сначала выберите другой. Изменение активного подключения создаёт новую сессию;
редактирование неактивного сохраняет текущую историю. Старый адрес и его история не передаются новому серверу.
Старый явный синтаксис `/provider add|set NAME URL [MODEL]` сохранён для работы с реестром.

Все стандартные пути провайдеров и auth.json находятся в GWAGENT_HOME (по умолчанию ~/.gwagent); --providers-file/--file остаются явным исключением. Для переноса со старого ~/.config/gwagent используйте `gwagent data migrate`; относительные TLS-пути при переносе сохраняют назначение через преобразование в абсолютные. [Единое хранилище](data.md).


## Параметры моделей и обмен OpenCode

У подключения доступны name, model_names (словарь ID → имя) и model_profiles с лимитами и
options для каждой модели. Старый список models, метки, mTLS, Basic, env/stored-ключи
сохраняются. configure_model меняет только данные модели после полного ввода и проверки.
В F3 доступны параметры моделей, импорт и экспорт. Команды оболочки: import-opencode,
export-opencode, model-config; импорт по умолчанию только проверяет, запись — с --apply.
[Формат и ограничения обмена](opencode.md). save_connections обновляет реестр и набор ключей
под блокировками обоих файлов с восстановлением auth при обычной ошибке записи реестра.

Каталог /models сохраняет числовые метаданные окна и aliases; выбор одинакового ID на другом подключении использует его собственный каталог. model_profiles.ID.context_window задаёт полное окно вручную, max_input_tokens — отдельный лимит входа (0 — авто). API-метаданные не записываются в providers.json и не переопределяют явные профили.

## Единые команды управления

Код: agent/provider_commands.py. Один разбор аргументов и один обработчик используются
обычным CLI, OpenTUI и `gwagent provider …` в оболочке. Поддерживаются кавычки, табуляция,
алиас `/providers`. Неверные аргументы и EOF показывают ошибку и сохраняют работу сессии.
Для всех операций модель не нужна; проверка check выполняет только GET models.

| Команда в чате | Результат |
|---|---|
| `/provider` | Подключения и общие действия; в TUI — выбор стрелками/мышью, в CLI — номером |
| `/provider list` | Подключения и фактические пути providers.json/auth.json |
| `/provider manage [NAME]` | Меню одного подключения: выбор, URL/авторизация, модели, проверка, default, включение/удаление |
| `/provider add [NAME]` | URL → способ авторизации → ключ/сертификат; затем сохранение и выбор |
| `/provider edit [NAME]` | Редактирование; при пропуске имени сначала выбор провайдера |
| `/provider use [NAME]` | Выбор подключения с сохранением для следующего запуска; `/provider NAME` — прежний короткий вариант |
| `/provider default [NAME]` | Default для следующего запуска, без переключения текущей сессии |
| `/provider model [NAME] [MODEL]` | Выбор провайдера/модели и ввод параметров; можно указать новый ID |
| `/provider check [NAME]` | Проверка подключения и обновление метаданных каталога без генерации |
| `/provider enable [NAME]` / `/provider disable [NAME]` | Включение/отключение; выбор предлагает подходящие записи |
| `/provider remove [NAME]` | Выбор доступной записи, затем подтверждение удаления; файлы PEM и сессии не удаляются |
| `/provider reload` | Перечитать providers.json после ручной правки; смена адреса активного подключения создаёт новую сессию |
| `/provider import` / `/provider export` | Прежний проверяемый обмен OpenCode без секретов в экспорте |
| `/provider help` | Синтаксис команд |

В оболочке используется тот же синтаксис без слеша: `gwagent provider edit`,
`gwagent provider model NAME MODEL`, `gwagent provider list --providers-file FILE`.
Bun и модель не запускаются, MCP тоже. Поддерживаются --cwd, --settings, --providers-file.
`/provider use @gateway` выбирает gateway из settings.json; этот выбор тоже сохраняется.
Прежние add/set NAME URL [MODEL], /connect [NAME] и gwproviders сохранены.

Новый мастер умеет выбирать env — имя переменной с ключом. Он сохраняет существующий
способ авторизации по Enter; в TUI соответствующий вариант выбран сразу. Для Bearer
и Basic Enter сохраняет прежний секрет только при том же URL (у Basic также тот же логин).
При mTLS сохраняются пароль ключа и дополнительная Bearer/Basic-авторизация при неизменном
адресе; явное переключение на Bearer/Basic/none снимает TLS, как раньше.

Подготовка подключения и модели не пишет файлы. Сохранение выполняется после возврата
данных в основной цикл; отменённый рабочий поток не может позднее записать конфигурацию.
Проверка версии файла защищает от одновременной правки другим процессом. /provider reload
перечитывает только реестр провайдеров; для изменений общих settings.json перезапустите CLI.

### Раздел «Провайдеры» в TUI

В TUI провайдеры открываются отдельным разделом главного меню: `/providers` и F3 показывают
четыре действия — посмотреть, добавить, изменить, удалить. Каждое действие сначала выбирается
списком, затем выбирается объект и заполняются нужные поля.

- Посмотреть: список подключений с URL; для выбранного — сведения, «Использовать» и
  дополнительные действия (проверка, модели, назначение по умолчанию, отключение).
- Добавить: два варианта — Base URL и токен либо Base URL и сертификат. Способ авторизации
  выбран заранее, поэтому мастер спрашивает имя, URL и ключ либо файлы PEM и пароль ключа.
  Новое подключение не становится текущим и не меняет default.
- Изменить: сначала выбирается провайдер, затем ровно одно поле — новый Base URL или новый токен.
  Смена адреса не переносит старый ключ на другой сервер: адрес и токен меняются отдельно.
  Изменение активного подключения с новым адресом создаёт новую сессию.
- Удалить: выбор провайдера и подтверждение. Текущее подключение и default удалить нельзя,
  пока не выбрано другое.

Страницы раздела: `/providers`, `/_ui/providers/view`, `/_ui/providers/add`, `/_ui/providers/edit`,
`/_ui/providers/remove`, `/_ui/provider/view NAME`, `/_ui/provider/edit NAME`,
`/_ui/provider/advanced NAME`. Esc возвращает предыдущее окно с прежним черновиком.
Команды чата (`/provider add`, `/provider edit`, `/provider remove` и остальные) сохранены
и работают как раньше. [Главное меню и переходы](tui.md).

### Где править параметры вручную

По умолчанию общий каталог — ~/.gwagent (либо GWAGENT_HOME). Провайдеры и индивидуальные
параметры: providers.json → providers.NAME.model_profiles.MODEL. Ключи: отдельный auth.json.
Общие настройки: settings.json → model_profiles/model_options, max_input_tokens/max_output_tokens.
В коде DEFAULTS находятся в agent/settings.py, резервное окно FALLBACK_WINDOW=120000 и каталог
паспортных размеров — agent/model_limits.py. Обнаруженные API-лимиты хранятся в памяти.

Фрагмент внутри существующей записи providers.NAME:

```json
"model_profiles": {
  "my-model": {
    "context_window": 131072,
    "max_input_tokens": 0,
    "max_output_tokens": 4096,
    "options": {"temperature_value": 0.3, "top_p": 0.9}
  }
}
```

context_window — полное окно, max_input_tokens=0 — автоматический доступный вход с резервом
ответа. В мастере можно отдельно изменить полное окно, лимит входа и лимит выхода;
`max_output_tokens: 0` означает «без ограничения» — `max_tokens` не отправляется, длина ответа
задаётся рекомендацией в промпте.

Удаление записи и её сохранённого секрета также согласовано под блокировками: если запись
providers.json не удалась, прежний auth.json восстанавливается, провайдер остаётся доступен.
Повторный выбор уже активного неизменившегося подключения сохраняет текущую сессию.

`/provider connect [NAME]` — алиас /connect; доступен и в gwagent provider connect.

В TUI `/providers` явно присутствует в каталоге как алиас `/provider`. Команды управления без
имени открывают общий список провайдеров; текущие/защищённые и отключённые подключения
показываются с учётом доступности действия. Добавление, импорт/экспорт и перечитывание сначала
открывают выбор действия, затем запускают прежний мастер. `/connect` предлагает настройку
текущего подключения, добавление нового или выбор сохранённого.
