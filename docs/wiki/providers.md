# Менеджер провайдеров

Код: `agent/providers.py`. Общий реестр подключений для [CLI агента](cli.md) и
[бенчмарков](bench/README.md). Без дополнительных зависимостей, протокол — OpenAI-совместимый
chat/completions с потоковыми ответами. Каждый провайдер задаёт URL, модель и переменную
окружения для Bearer-ключа; пустой token_env означает отсутствие авторизации.

Именованные подключения и выбор модели основаны на том же подходе, что в
[OpenCode](https://opencode.ai/docs/providers/). Формат конфигурации здесь собственный;
подключения с другими протоколами требуют OpenAI-совместимого API перед ними.

## Управление

```bash
venv/bin/python -m agent.providers list
venv/bin/python -m agent.providers add local --url http://127.0.0.1:8000/v1 --model my-model
venv/bin/python -m agent.providers add cloud --url https://example.org/v1 --token-env CLOUD_API_KEY --model vendor/model
venv/bin/python -m agent.providers models local
venv/bin/python -m agent.providers use local --model my-model
./gwagent --provider local -p 'Расскажи о себе'
venv/bin/python -m bench --provider local --suites tools,structured,chain --quick
venv/bin/python -m agent.providers remove cloud
```

Флаг `--file FILE` перед подкомандой выбирает иной реестр. Потребители используют
`--providers-file FILE`. `list` не обращается в сеть; `models` вызывает GET models относительно
указанного API URL. Тело ошибок каталога не выводится. Для API без каталога задайте модель
явно; `models` в конфигурации хранит справочный список ID и отображается в list.

`use` сохраняет default и при необходимости модель. Активный default нельзя удалить,
сначала нужно выбрать другой. `add` не перезаписывает существующие записи; для изменения
URL отредактируйте JSON. Код выхода менеджера: 0 — успех, 2 — ошибка.

## Файл и приоритеты

Стандартный путь: `~/.config/gwagent/providers.json`. Файл создаётся при первой изменяющей
команде, запись атомарная, права 0600. До создания доступна виртуальная запись gateway.

```json
{
  "default": "local",
  "providers": {
    "gateway": {
      "url": "http://127.0.0.1:7700/v1",
      "token_env": "GW_TOKEN",
      "model": "",
      "models": []
    },
    "local": {
      "url": "http://127.0.0.1:8000/v1",
      "token_env": "",
      "model": "my-model",
      "models": ["my-model", "vendor/another-model"]
    }
  }
}
```

Все показанные поля обязательны при ручном редактировании; неизвестные ключи запрещены.
Имя провайдера: латинские буквы, цифры, `_`, `-`. URL — HTTP(S), без встроенных учётных данных,
query и fragment. В token_env записывается имя переменной, её значение в JSON не попадает.
Если переменная задана в конфигурации, но отсутствует или пуста в окружении, запрос запрещён.
Model ID может содержать `/` и передаётся API без изменения. Справочный список models не
ограничивает выбор --model и не подменяет сетевой каталог.

Порядок выбора: явный --provider → default из существующего реестра → прежнее подключение
шлюза. --providers-file выбирает default указанного файла. В бенчмарках явный --url обходит
стандартный реестр; сочетание с явными флагами провайдера запрещено.
--model имеет приоритет над моделью провайдера. Агент при пустой модели запрашивает первую
из каталога; бенчмарки требуют явную модель или заполненное поле model у провайдера.

Реестр не меняет mTLS-апстрим серверного шлюза и настройки серверных профилей. Интерактивные
команды /provider и /models описаны в [cli.md](cli.md); привязка сессии — в [sessions.md](sessions.md).

## Проверки

`tests/test_providers.py`: добавление, выбор, удаление, повторное чтение, права файла,
скрытие ключей, ошибочные URL, отсутствующая переменная, сетевой каталог и HTTP-ошибки.
`tests/test_cli.py`: переключение провайдера с новой сессией, восстановление привязки,
конфликт явного выбора и сессии. `tests/test_bench.py`: передача подключения, модель и
имя провайдера в отчёте. Все проверки офлайн.
