# Архитектура

```
                      ┌──────────────── gateway/ (FastAPI, один процесс uvicorn :7700) ─────────────────┐
 openai SDK, cliAgent ─┤ /v1/*  прокси байт-в-байт ─────────────────────────────┐                        │
                      │                                                         ├─ mTLS-клиент httpx ───┼─▶ инференс
 веб-чат /chat/ ───────┤ /agent/* agent_api.py ─▶ agent/ (ядро) ─ LLMClient ────┘  (сертификат шлюза)   │
                      │                          │  инструменты на сервере                              │
                      │ tokens.py: токены gw-…, usage  ·  data/gateway.db: токены + сессии агента       │
                      └─────────────────────────────────────────────────────────────────────────────────┘

 gwagent (любая машина) ─ agent/ (то же ядро) ─ LLMClient ─Bearer gw-…─▶ шлюз /v1/chat/completions
                          │ инструменты, MCP, хуки — локально; сессии — ~/.gwagent/sessions.db
```

## Путь одного шага агента

1. Фронт (CLI / `/agent/sessions/{id}/messages`) создаёт `Agent` через `runtime.make_agent`.
2. `Agent.run` → хуки → `LLMClient.stream` с историей из `SessionStore` и `Registry.specs()`.
3. Модель вернула `tool_calls` → для каждого: `parse_arguments` → `Tool.check_args` (схема) →
   `PreToolUse` → `Permissions.decide` → (`approver`) → `Tool.run(args, ToolContext)` → `PostToolUse`.
4. Всё сохраняется в SQLite сразу; события уходят фронту (печать / SSE).

## Свой инструмент

```python
from agent.tools.base import Tool, ToolError

class Weather(Tool):
    name = "weather"
    description = "Погода в городе"
    parameters = {"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]}
    default_permission = "allow"              # или "ask"

    def subject(self, args):                  # для правил weather(Моск*)
        return args["city"]

    async def run(self, args, ctx):           # ctx.workspace, ctx.settings, ctx.session_id
        if not args["city"]:
            raise ToolError("пустой город")   # уйдёт модели как ошибка
        return "солнечно"                     # str или ToolResult(content, is_error)
```

Затем добавить класс в `TOOLS` своего модуля и в `BUILTIN` (`agent/runtime.py`), имя — в
`DEFAULTS["tools"]["enabled"]`, тесты — `tests/test_tools_<модуль>.py`, страницу — `docs/wiki/tools/`.
`tests/test_wiki.py` напомнит, если страница забыта.

## Решения

- **Без фреймворков**: протоколы (OpenAI chat/completions, MCP JSON-RPC, SSE) реализованы напрямую —
  это несколько сотен строк, зато видно и тестируемо каждое поведение.
- **Сервер зовёт инференс напрямую**, а не через свой `/v1`: нет лишнего HTTP-круга и второй
  аутентификации; расход всё равно пишется в `usage` (путь `agent`).
- **Вызовы инструментов — последовательно**, история пишется после каждого шага: отмена или
  падение процесса не ломают сессию.
- **Системный промпт не хранится** — собирается из текущих настроек.

## Общие механизмы локального агента

Подключения и TLS собирает providers, секреты обслуживает credentials, приватные атомарные
файлы и блокировки — storage, доверие проектному конфигу — trust. Диагностика doctor не
запускает инструменты. SSE разбирается общим streaming. Эти модули не импортируют FastAPI.
SQLite сериализует операции на соединение; файловые операции вынесены из event loop,
регулярные выражения исполняются в отдельном останавливаемом процессе.
Установка CLI описана в [cli.md](cli.md), источники настроек — в [settings.md](settings.md).

## OpenTUI

Необязательный Bun-клиент `tui/src` связан JSONL с `agent/tui_backend.py`, который использует
тот же `cli.App`: история, права, провайдеры и инструменты остаются в Python.
`agent/tui.py` выбирает режим и устанавливает UI в пользовательский кэш; assets входят в wheel.
[Установка, представление ответов и протокол](tui.md).

Интерактивный `App` создаёт/возобновляет локальную сессию до создания LLM-клиента.
Локальный `Connection` содержит только метаданные; `model_client()` загружает auth/TLS при
`/models` или первом сообщении. После выбора модели `ask()` собирает агент.
Ошибка такой подготовки завершает запрос, сохраняя REPL/backend для настройки.
Одноразовые запросы `-p` сохраняют прежнюю строгую инициализацию.

Меню по `/` получает `snapshot.catalog` от `tui_commands.navigation_catalog()` в JSONL-мосте:
в каталоге только разделы главного меню с названием, описанием и алиасами поиска.
OpenTUI фильтрует и выбирает пункты локально через общий ChoiceList, сохраняя фокус
в Textarea. `/tools NAME` возвращает справку и параметры; произвольное выполнение инструмента
из меню не добавлено. Подробности: [OpenTUI](tui.md).

`App.all_models()` собирает каталоги включённых подключений независимо (до четырёх запросов,
10 секунд на источник), использует `resolve_connection()` без изменения активного клиента.
Ошибка источника оставляет его известные модели из конфига и предупреждение. CLI и TUI
используют общий агрегатор. Bridge кэширует предложенные пары и ID сессии отдельно для моделей
и провайдеров. Сообщение `select` проверяется и исполняется одной задачей: для другого провайдера
`App.choose_model()` создаёт сессию с выбранной моделью, для того же обновляет прежнюю.

## Общие компоненты терминальных окон

TUI разделён на `theme.ts` (цвета и плашки), `menus.ts` (реестр/адаптеры/горячие клавиши),
`choice.ts` (список с группами, прокруткой и мышью), `view.ts` (состояния, события и фокус).
Модели, провайдеры, сессии, инструменты, MCP и дискретные диалоги используют один ChoiceList.
Системные уведомления визуально отделены от пользовательских и модельных сообщений.

Bridge выдаёт сессии только OWNER=local и проверяет выданные ID перед возобновлением/удалением.
`App.activate_session` проверяет workspace/endpoint до смены клиента. Возобновление остаётся
локальной операцией; удаление отдельно подтверждается с безопасным первым вариантом.
Выбор инструмента/MCP открывает справку. Параметры инструмента и содержание ответа остаются
табличными данными и не превращаются в исполняемые пункты.

## Корреляция действий

`agent/tracing.py` хранит request/span в ContextVar; цикл создаёт вложенные span для
модели и инструмента, а SQLite сохраняет журнал независимо от обработчиков logging.
Сабагенты создаются самим циклом без внешних фреймворков, отдельная история и общий
бюджет сохраняют связь с запросом пользователя. Подробнее: [цикл](agent-loop.md), [сессии](sessions.md).

## Локальная история файлов

Контрольные точки `agent/checkpoints.py` + SQLite — встроенный аналог истории Git:
объекты по SHA-256, дедупликация версий, деревья до/после запроса и родительский request_id.
Реальный Git-репозиторий не используется. Старые ветки диалога сохраняются при rewind;
новая ветка наследует последнюю оставшуюся активную контрольную точку.
Подробнее: [сессии](sessions.md).

Пакет OpenTUI включает `terminal-input.ts`: обёртка stdin собирает служебные OSC/DCS-пакеты
до парсера клавиатуры. `main.ts` закрывает обёртку после renderer, а `view.ts` использует
встроенный clipboard OpenTUI для локального буфера и OSC 52; новые зависимости не нужны.
Файл включён в data-files wheel и в хеш кэша установки TUI.

Запрос разрешения отделён от формы ввода: `tui/src/approval.ts` использует общий ChoiceList
в quiet-режиме и сохраняет прежний протокол approve. Компонент включён в wheel. Редактор
может держать следующий черновик во время модельного запроса; разрешение остаётся модальным.

Правая панель TUI вынесена в `sidebar.ts`: состояние контекста/плана/MCP отделено от
замечаний, извлечённых из ответа. Новый модуль включён в wheel. JSONL-мост собирает
read-only snapshot и dashboard, события context приходят из общего цикла.
`runtime.BUILTIN` включает классы Goal/Todo из tools/planning.py. Их состояние хранится в
существующих метаданных сообщений, без таблиц, миграций и новых зависимостей; это сохраняет
совместимость с откатом ветки. Подробно — [планирование](tools/planning.md).

Активные агенты build/plan реализованы поверх того же Agent, без второго фонового цикла
и новых зависимостей. Общая история и план принадлежат сессии; режим хранится в SQLite 5.
runtime собирает общий реестр, Agent.tool_specs ограничивает видимые модели инструменты,
а выполнение дополнительно проверяет Tool.plan_safe. Меню инструментов учитывает режим.
Интерактивный questioner внедряется через make_agent: CLI читает ответ, мост OpenTUI использует
свои futures/диалоги. Без получателя вопрос завершается ошибкой с инструкцией задать его текстом.
JSONL-мост откладывает смену режима работающего запроса до завершения и сохраняет его права.

Живые уточнения OpenTUI проходят отдельной командой steer, а не вторым App.ask.
App.active_request_id связывает вход с текущим циклом даже во время инициализации клиента;
SessionStore (SQLite 6) хранит FIFO до безопасного применения. Общий Agent обрабатывает
очередь между шагами и закрывает tool-call/result группы перед вставкой user.
Сегменты checkpoint_id позволяют откатывать уточнения, сохраняя предшествующие изменения.
Новых зависимостей, фонового агента или параллельного обращения модели не требуется.

`agent/data.py` — единственная точка вычисления GWAGENT_HOME и путей хранения, а также явный перенос старых данных. Модули настроек, провайдеров, credentials, trust, TUI и бенчмарков используют этот каталог. Подробности: [единое хранилище](data.md).


agent/opencode.py выполняет явное преобразование поддерживаемого поднабора OpenCode
в существующий реестр. Хранение не дублируется и AI SDK не подключается. Метаданные
имён и профили моделей находятся у провайдера, секреты отдельно. [Совместимость](opencode.md).

Роли исследователя/ревьюера реализованы обычным Agent с отдельным промптом и реестром
plan_safe инструментов, без фреймворков. runtime включает inspect из tools/inspection.py:
проверки программы/пути и HTTP HEAD используют stdlib и существующий сетевой клиент.
