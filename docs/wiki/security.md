# Безопасность

Агент выполняет действия, которые придумала модель. Модель может ошибиться или быть обманута
текстом, который сама прочитала (prompt injection: страница из `web_fetch`, файл, ответ MCP).
Поэтому опасные действия ограничиваются кодом, а не промптом.

## Модель угроз

| Угроза | Защита | Остаточный риск |
|---|---|---|
| Выход файловых инструментов из рабочей папки | `resolve()` + проверка, что путь внутри; симлинки раскрываются ([tools/files.md](tools/files.md)) | `shell` этих границ не знает |
| Опасная команда `shell` | по умолчанию **ask**; `deny`-правила; хук `PreToolUse` (пример — `config/hooks/check_shell.py`); урезанное окружение; таймаут и убийство группы ([tools/shell.md](tools/shell.md)) | **не песочница**: подтверждённая команда может всё, что может пользователь процесса |
| Утечка секретов в команды | `shell.env_passthrough` — только `PATH`, `HOME`, `LANG`…; токены процесса не передаются | файлы с секретами читаемы, если они доступны пользователю процесса |
| SSRF (запросы к внутренней сети, метаданным облака) | проверка всех адресов хоста и каждого редиректа; только http/https; списки доменов ([tools/web.md](tools/web.md)) | DNS rebinding между проверкой и соединением; для строгости — egress-прокси |
| Утечка данных наружу (`http_request` с содержимым файлов) | `web_fetch`/`http_request` — **ask**; `network.allow_domains` | `web_search` по умолчанию allow: запрос сам по себе может нести данные |
| Чужие сессии на сервере | сессия привязана к id токена, чужая = 404 | — |
| Самовольный доступ к агенту | только токены с `agent_profile`; профили задаёт администратор | — |
| Подмена хуков/настроек пользователем | на сервере хуки и MCP только в `config/agent.json` | в CLI проектный конфиг применяется только после доверия |
| Бесконечный цикл / расход токенов | `max_steps`, бюджеты контекста и хода, rpm и allowlist токена, учёт в `usage` | — |

## Сервер (многопользовательский режим)

Инструменты серверного агента работают **от пользователя, под которым запущен шлюз**, на этой машине.
Рекомендации:

1. Запускать шлюз под отдельным системным пользователем без sudo и без доступа к чужим данным
   (сейчас юнит пользовательский — `deb`: всё, что доступно `deb`, доступно подтверждённой команде).
2. В профиле по умолчанию — `"deny": ["shell"]` или узкие `allow`-правила + хук-политика;
   `allow_all` — только доверенным токенам.
3. `workspace_root` — на отдельном разделе/каталоге; лимиты диска — средствами ОС (quota).
4. Для изоляции `shell` — обёртка в `shell.executable` (`bwrap`, `firejail`, контейнер).
5. `MemoryMax` юнита ограничивает и дочерние процессы агента (они в той же cgroup).
6. Шлюз отдаёт HTTP: снаружи локальной сети — только за nginx с TLS (токены и подтверждения идут
   в заголовках/телах).

## CLI

`gwagent` работает с правами того, кто его запустил, в текущей папке. По умолчанию каждая запись в
файл, команда, HTTP-запрос и вызов MCP требуют подтверждения. `--allow-all` — только в папках и
задачах, которым доверяете. Токен шлюза — из переменной окружения, в команды не передаётся.

## Хранение

- В SQLite сессий лежит полная история, включая содержимое прочитанных файлов и вывод команд.
  Права на `data/` и `~/.local/share/gwagent/` — только владельцу. Удаление сессии (`DELETE`,
  на сервере) удаляет историю и рабочую папку.
- Тексты запросов к `/v1` шлюз по-прежнему не логирует; агентские — хранит, потому что без истории
  сессию нельзя продолжить.

## Изменения после аудита

Проектный конфиг требует явного доверия отпечатку (trust), иначе не применяются ни его URL,
ни хуки/MCP. Это доверие к коду проекта, не проверка безопасности каждой команды.
HTTP-инструменты не следуют редиректу на другой origin автоматически: для нового адреса
нужен новый разрешённый вызов. Остаточный риск DNS rebinding остаётся, см. таблицу выше.
Auth.json и TLS-файлы закрыты файловым инструментам; права и маскирование описаны в
[providers.md](providers.md). Запрет не создаёт песочницу для разрешённого shell или доверенного MCP.
Секреты, введённые вне менеджера, нельзя гарантированно распознать; старые истории не очищаются.
Shell и хуки очищают процессы на отмене, grep ограничен отдельным процессом и таймаутом.
Число шагов дополнено бюджетом контекста/ответа/хода. Однопроцессный сервер имеет ограниченные
очереди, общий лимит моделей и проверку отзыва прав; распределённые квоты не реализованы.
