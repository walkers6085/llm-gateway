# Уточняющие вопросы

Код: [`agent/tools/question.py`](../../../agent/tools/question.py).

`question` позволяет модели приостановить выполнение инструмента до ответа пользователя.
Он включён в стандартный `tools.enabled`, имеет `allow` и доступен агентам build/plan.
Если задан собственный список инструментов, добавьте имя `question` в него.

```json
{"question":"Какой формат экспорта нужен?","options":["JSON","CSV"]}
```

Вопрос — непустой текст до 4000 символов. Необязательные options — до 8 уникальных вариантов
по 200 символов. В OpenTUI можно выбрать стрелками/Tab/мышью, написать свой ответ либо
пропустить вопрос через Esc. Свободный ответ доступен и при наличии вариантов.
Ответ ограничен 16000 символами; инструмент возвращает `{"answer":"CSV"}` либо
`{"cancelled":true}` при пропуске/таймауте. Пропуск не отменяет весь запрос.
Существующий следующий черновик восстанавливается после ответа или закрытия вопроса.
Ctrl+C сохраняет обычную отмену текущего запроса и ремонт истории tool-call/result.

В обычном CLI вводится номер варианта или текст; Enter пропускает вопрос. Интерактивный
получатель передаётся через `Agent.questioner`, в ToolContext доступен через extra.questioner.
Таймаут ожидания асинхронного получателя — permissions.timeout (600 секунд по умолчанию).
Без интерактивного получателя (например, серверный API без адаптера вопросов либо -p/--json
без TTY) инструмент возвращает понятную ошибку с предложением задать вопрос обычным ответом;
он не ждёт ответа бесконечно. Никаких новых серверных эндпоинтов не добавлено.

Вопрос и ответ проходят стандартную маскировку при сохранении. В трассировке question.start/end
имеют общий request_id и span инструмента; ответ сохраняется как результат tool-сообщения.
Отмена, ошибка и таймаут закрывают ожидание. Подтверждения действий и ответы на вопросы
используют разные типы сообщений JSONL; ответ на вопрос не считается разрешением инструмента.

В Plan вопрос задаётся до фиксации плана, когда нужны предпочтения или существенный
выбор пользователя. В Build — при обнаружении недостающего требования. Модель должна
сама проверять доступные факты; вопрос не заменяет inspect/чтение файлов. Рекомендуются
2–4 понятных варианта со свободным ответом. Отмена вопроса не означает согласие и не
позволяет угадать критическое решение. Ответ не переключает режим и не меняет права.
