# Сабагент

Код: `agent/tools/subagent.py`, выполнение — `agent/loop.py`.

Инструмент `subagent` принимает `{"task": "самостоятельная задача"}` (1–16000 символов).
Родитель получает ToolResult с ответом ребёнка; ошибки/таймаут имеют is_error.
Обычные настройки прав применяются к самой делегации и всем дочерним инструментам.
Модель и workspace наследуются, контекст беседы начинается с новой задачи.
Вложенная делегация исключена из реестра ребёнка. Лимиты описаны в [настройках](../settings.md),
события — в [цикле](../agent-loop.md), идентификаторы — в [сессиях](../sessions.md).

## Внутренние роли в Plan и Build

Параметр role: explorer (сбор фактов), reviewer (независимая проверка), worker (реализация).
Без role в Build остаётся worker для совместимости; в Plan/read_only выбирается explorer.
Необязательный context (до 16000 символов) передаёт нужные факты и пути отдельно от задачи.
Обе роли исследования используют отдельный промпт и реестр только plan_safe инструментов,
без shell, записи файлов, произвольных HTTP-запросов, MCP и вложенной делегации.
Worker недоступен в Plan/read_only даже после разрешающего или меняющего аргументы хука.
Отдельный вопрос/подтверждение не расширяет права ребёнка.

Встроенные инструкции Plan требуют сначала выполнить доступные проверки, затем составить
план с конкретными файлами, действиями и критериями готовности. Общие фразы «проверить
доступность» не заменяют результат доступной проверки. Для неизвестных/заблокированных
фактов указываются причина и нужное уточнение. Исследование самостоятельных направлений
и ревью существенного плана рекомендуется делегировать. Build использует explorer до
реализации и reviewer после значимых изменений. Для простых ответов делегация не обязательна.
Выбор вызова остаётся за моделью; роли не запускаются принудительно на каждый запрос.
Роли исполняются последовательно и разделяют общий лимит дочерних вызовов и токен-бюджет.

Explorer/reviewer скрыты из обычного списка сессий. Их история доступна по ID, в журнале
и статистике. SessionStore.list(include_internal=True) включает их для диагностики.
Маркер session.internal сохраняется в собственной сессии ребёнка, поэтому удаление
родительской сессии не делает внутреннюю сессию видимой. Это организация списка,
а не отдельная граница доступа: проверка владельца сохраняется.
Поля role/hidden передаются в subagent_start, role — также в subagent_end и трассировках.
