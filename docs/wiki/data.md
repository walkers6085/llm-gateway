# Единый каталог данных

Код: `agent/data.py`. Тесты: `tests/test_data.py`.

Все стандартные данные агента находятся в одном каталоге. По умолчанию — `~/.gwagent`.
Можно выбрать отдельный каталог вне репозитория или переносимую папку рядом с CLI:

```bash
export GWAGENT_HOME=/srv/gwagent
# Либо переносимый вариант (абсолютный путь надёжнее при смене cwd):
export GWAGENT_HOME="$PWD/.gwagent-data"
./gwagent data
# В открытом чате: /data
./gwagent tui install
./gwagent --tui
```

| Путь внутри GWAGENT_HOME | Содержимое |
|---|---|
| settings.json | Общие настройки, включая секцию mcp и хуки |
| providers.json | URL, модели, параметры подключений |
| auth.json | Ключи и пароли, права 0600 |
| trust.json | Доверие проектным конфигурациям |
| sessions.db | История, запросы, инструменты, метрики, снимки для /revert |
| cache/tui/ | Исходники и зависимости установленного TUI |
| workspaces/ | Рабочие папки серверного агента по умолчанию |
| bench/ | Отчёты бенчмарков по умолчанию |

Служебные .lock, SQLite -wal/-shm и временные файлы создаются рядом с соответствующими
данными. Файлы проектов CLI остаются в текущем workspace или --cwd; их не переносят
в каталог настроек. GWAGENT_HOME передаётся shell-инструменту через стандартный
список env_passthrough и MCP-процессам через окружение. Каталог для данных должен быть отдельным, не выбирайте корень
исходников проекта: служебное дерево защищено от файловых инструментов и снимков,
кроме явно предназначенного для задач workspaces/.

Пути --settings, --providers-file/--file, sessions.db и --output остаются явными исключениями.
Необязательный проектный .gwagent/settings.json также работает с прежней проверкой доверия;
для общей настройки MCP и провайдеров он не нужен. Сертификаты PEM можно положить в certs/
внутри общего каталога и использовать относительные пути в tls. Внешние PEM-файлы
автоматически не копируются. Конфиги сторонних MCP-серверов можно явно направить в mcp/
через args/env, но агент не меняет их HOME и внутреннюю логику хранения.

## Перенос со старой версии

Завершите работающие CLI перед переносом. Выберите GWAGENT_HOME и запустите:

```bash
./gwagent data migrate
./gwagent tui install
```

Переносятся settings.json, providers.json, auth.json и trust.json из ~/.config/gwagent,
а также ~/.local/share/gwagent/sessions.db. Необходимо, чтобы соответствующие файлы
назначения ещё не существовали. При любом конфликте копирование не начинается;
частично существующий набор автоматически не сливается и не перезаписывается.
Исходные файлы остаются резервной копией. Старые файлы штатным запуском больше не читаются.

JSON готовится до публикации, auth.json с небезопасными правами или симлинком отклоняется.
SQLite копируется backup API с учётом WAL и проверяется quick_check. Подготовленные файлы
публикуются без перезаписи с правами 0600, при обычной ошибке публикации созданные файлы
убираются. Это не транзакция нескольких файлов с гарантией при отключении питания.
Не запускайте одновременно перенос и запись в новый каталог другими процессами.

Старое стандартное sessions.db в settings.json заменяется ссылкой на GWAGENT_HOME;
явные нестандартные пути сохраняются. Относительные TLS-пути превращаются в абсолютные
пути старого каталога, чтобы сертификат продолжал открываться. Собственные args/cwd
сторонних MCP-серверов не переписываются. Кэш TUI переустанавливается из lockfile;
отчёты, рабочие папки, внешние базы, сертификаты и произвольные файлы нужно перенести отдельно.

Для переноса на другую машину остановите процессы и скопируйте весь каталог с сохранением
прав; абсолютные пути к сертификатам, исполняемым MCP-серверам и проектам могут требовать
правки. История сессий привязана к workspace и подключению, реестр доверия — к пути проекта.

Конфигурация самого шлюза (.env, config/agent.json и DB_PATH с общей базой токенов) остаётся отдельной серверной настройкой: её эта миграция не переносит. Настройки MCP в серверных профилях по-прежнему задаёт владелец шлюза; общий settings.json используется локальным CLI.
