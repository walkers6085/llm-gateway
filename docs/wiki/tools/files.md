# Инструменты: файлы

Код: [`agent/tools/files.py`](../../../agent/tools/files.py). Тесты: [`tests/test_tools_files.py`](../../../tests/test_tools_files.py).

Все пути — относительно рабочей папки сессии (CLI — текущая папка или `--cwd`, сервер —
`<workspace_root>/<токен>/<сессия>`). Путь проходит через `Path.resolve()` (симлинки раскрываются)
и обязан остаться внутри рабочей папки: `../x`, `/etc/passwd`, симлинк наружу → ошибка
«вне рабочей папки». Текст читается как UTF-8 (битые байты заменяются), файлы с NUL в первых 8 КБ
считаются двоичными.

| Инструмент | Права по умолчанию | Аргументы | Результат |
|---|---|---|---|
| `read_file` | allow | `path`, `offset` (с 1), `limit` (2000) | строки `номер⇥текст`, пометка, если показана не вся длина |
| `write_file` | ask | `path`, `content` | создаёт папки; «Создан/Перезаписан путь (N байт)» |
| `edit_file` | ask | `path`, `old_string`, `new_string`, `replace_all` | точная замена; `old_string` должен быть уникален, иначе — ошибка с числом вхождений |
| `list_dir` | allow | `path` (по умолчанию корень) | папки (`имя/`) первыми, у файлов — размер; до 500 строк |
| `glob` | allow | `pattern` (`**/*.py`), `path` | отсортированный список; до 500 |
| `grep` | allow | `pattern` (Python `re`), `path`, `include` (`*.py`), `ignore_case` | `файл:строка:текст`, до 200 совпадений, строки режутся до 300 символов |

`glob` и `grep` пропускают `.git`, `node_modules`, `venv`, `.venv`, `__pycache__`, кэши; `grep` не
ходит по симлинкам и пропускает файлы больше `files.max_read_bytes` и двоичные.

Предмет для правил прав — нормализованный путь: `write_file(docs/*)`, `read_file(.env*)`.

## Ограничения

- Нет блокировок: два агента в одной папке могут перетереть правки друг друга.
- `read_file` не помнит, что файл был прочитан — `edit_file` полагается на точное совпадение фрагмента.
- Размер `write_file` не ограничен отдельно (ограничен телом запроса к модели).

## Атомарная запись, конфликт и пределы поиска

Чтение/запись/обход выполняются вне event loop. ReadFile сохраняет отпечаток прочитанного файла
в контексте сессии; последующая запись при несовпадении отклоняется до изменения файла.
write_file/edit_file также принимают `expected_sha256` и `preview=true` для просмотра unified diff
без записи. edit_file дополнительно проверяет отпечаток между своим чтением и заменой.
Запись использует временный файл, fsync и atomic replace, сохраняя режим существующего файла.
Новые файлы получают 0600; результат ограничен files.max_read_bytes. Это обнаруживает конфликты,
но не даёт ОС-изоляцию от враждебной программы, одновременно меняющей дерево каталогов.

grep, glob и list_dir работают в отдельном spawn-процессе с общим files.timeout (10 секунд) и, для grep, максимумом
files.max_scan_files (1000). Отмена/таймаут завершают и дожидаются процесса; тяжёлая Python-regex
не блокирует цикл событий. Поиск пропускает зарегистрированные файлы учётных данных и TLS.
Блокировки записи хранятся в приватном каталоге /tmp/gwagent-locks-UID, а не среди файлов проекта.

Для агента plan чтение read_file, list_dir, glob и grep отмечено Tool.plan_safe=True.
write_file/edit_file не допускаются даже при allow_all; проверка выполняется ядром до хука.
