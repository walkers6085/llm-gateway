# Веб-чат

Код: [`chat/index.html`](../../chat/index.html) — одна страница без сборки и внешних библиотек, отдаётся
шлюзом на `/chat/` (статика: правки применяются без перезапуска). Проверка: тест страницы в
[`tests/test_agent_api.py`](../../tests/test_agent_api.py) и ручной прогон в браузере (ниже).

## Режимы

Переключатель в шапке: **Чат** / **Агент** (запоминается в `localStorage`).

| | Чат | Агент |
|---|---|---|
| Куда ходит | `POST /v1/chat/completions` (стрим) | `/agent/*` ([server-api.md](server-api.md)) |
| История | в памяти вкладки, теряется при перезагрузке | в SQLite на сервере, выбирается в списке сессий |
| Системный промпт, температура | блок «Системный промпт и параметры» | из профиля агента на сервере (блок скрыт) |
| Токену нужно | любой активный токен | токен с профилем агента (`./gwtoken agent <имя> <профиль>`) |

## Режим «Агент»

- **Сессии**: список «— новая сессия —» + сессии токена (по названию — начало первого запроса).
  Новая сессия создаётся при первом сообщении с выбранной моделью. Выбор сессии загружает её
  историю: реплики, карточки инструментов с результатами.
- **Карточки инструментов**: `✓`/`✗`/`…`/`?`, имя и краткие аргументы; по клику — аргументы
  целиком и результат (то, что увидела модель) с временем выполнения.
- **Подтверждение**: карточка раскрывается, кнопки «Разрешить / Запретить / Всегда»
  (`POST …/approve`). Пока никто не ответил, агент ждёт (`permissions.timeout` профиля).
- **Стоп**: `POST …/cancel` и разрыв потока — запрос отменяется, история остаётся корректной.
- Под ответом — время и токены за запрос (сумма по всем обращениям к модели), причина, если не
  обычное завершение (лимит шагов, отмена, ошибка, блокировка хуком).

Токен хранится в `localStorage` браузера (`gw_token`), id открытой сессии — `gw_agent_session`.

## Ручная проверка в браузере

Тестовый стенд (сценарный mTLS-апстрим, токен с профилем) поднимается из фикстур тестов:
`tests/fakes.py` (`make_pki`, `upstream`, `SCRIPT`, `ServerThread`) + `create_app(settings, store)`.
Сценарий — список ответов модели `{"content", "tool_calls": [tool_call(id, name, **args)]}`.
Так проверялись подтверждение `write_file`, вывод результатов и восстановление истории после перезагрузки
(headless Chrome через Playwright).
